## 3. 迁移与接口／配置变化

### 3.1 迁移

`SCHEMA_VERSION`: **2 → 3**。v3 只新增表与索引，**不修改既有表的列或数据**：

`analysis_jobs`、`analysis_attempts`、`analysis_steps`、`analysis_calls`、`analysis_results`。

关键不变式：

- 生成任务**不复用** `parse_tasks`（上游事实来源不同、状态机与预算语义不同）；
- `analysis_calls` 是费用事实来源：请求前预扣并写意图，保存已校验检查点后才结算；
- 结果正文与结果行同事务写入 `analysis_results.payload_json`，不存在“结果行有、正文缺失”；
- 旧库升级前的备份走 SQLite 在线备份 API（含 WAL 中已提交数据）。

**未对正式库执行迁移**；演练只在独立目录进行。

### 3.2 新增配置（`app/config.py`，已在 `.env.example` 说明）

| 变量 | 默认 | 校验 |
| --- | --- | --- |
| `DOCQA_ANALYSIS_MAX_REQUESTS` | 8 | 1～50 的整数 |
| `DOCQA_ANALYSIS_BATCH_MAX_CHARS` | 12000 | > 0 且 < `INPUT_MAX_CHARS` |
| `DOCQA_ANALYSIS_REDUCE_MAX_CHARS` | 16000 | > 0 且 < `INPUT_MAX_CHARS` |
| `DOCQA_ANALYSIS_INPUT_MAX_CHARS` | 20000 | > 0 |
| `DOCQA_ANALYSIS_MAX_DOCUMENT_CHARS` | 200000 | > 0 |
| `DOCQA_ANALYSIS_MAX_ITEMS_PER_BATCH` | 15 | 1～50 |
| `DOCQA_ANALYSIS_MAX_ITEMS_TOTAL` | 60 | ≥ 单批上限 |

非法值在启动阶段即被拒绝（见 `tests/test_analysis.py` 的配置相关断言与 A26）。

### 3.3 接口变化（默认契约，未改名）

| 接口 | 状态 |
| --- | --- |

| `POST /api/documents/{id}/summary` | 同上 |
| `GET /api/analysis-jobs/{job_id}` | 新增；状态、阶段、预算、覆盖、结果入口，不返回模型原始正文 |

| `GET /api/documents/{id}/analysis-jobs` | 新增；任务历史 |
