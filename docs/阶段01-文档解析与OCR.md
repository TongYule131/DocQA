# 阶段01：文档解析与OCR

更新：2026-10-22。当前状态见[接力说明](稳定试用版接力说明.md)，运行配置见[Docling部署](../deploy/docling/README.md)。本文件汇总正式能力、量化标准和实验；冻结版本在[历史归档](archive/README.md)。

## 正式解析链路

支持PDF、DOCX、XLSX、UTF-8 TXT和Markdown。工程上传接口只保存原件；统一知识库入口按已采纳流程自动解析、分块和索引，预览／刷新不额外发起生成。解析任务、版本、来源和告警独立持久化。TXT和Markdown本地解析（Markdown保留标题结构），PDF／DOCX／XLSX使用既有Docling/RapidOCR服务；旧二进制DOC／XLS须先转换。知识库分块边界修订另建不可变草稿版本，必须保留完整原文及顺序；纠正文稿须上传新版原件，不直接改证据文字。当前schema14、新解析规范化为docqa-normalized-7，未更换正式OCR模型，以下历史实验成绩仍绑定原样本和当时版本。

正常PDF参数为rapidocr、ch、do_ocr=true、force_ocr=false、table_mode=accurate、JSON+Markdown；异常文本映射的定向分支见下节。不自动开启远程VLM、图片描述或公式重算。图片节点存在不代表内部文字/关系已可靠解析。通用ocr_limitation表示能力边界，不能写成已定位到OCR失败。

## 新建模PDF文本映射故障（2026-10-22）

用户新上传的20页建模论文原图可读，但原生文字提取大量变为控制字符，上游正文／表格变为装饰符号。原结果仍被建成索引，说明原质量检查仅有一般OCR提示，未拦截明显乱码。新增pdf-text-health-v1在首次提交前检测异常；仅命中时用PDFium／Pillow生成144DPI、同页同尺寸的图像PDF副本，再以force_ocr=true提交原有服务，不改上传原件、不追加自动重试。渲染受页数、单页2500万像素和提交大小约束，且串行调用PDFium；pypdfium2 5.14.0加入锁定依赖。转换后按页复核明显坏映射，仍异常则quality_invalid，保留旧版本。

首次只强制OCR恢复了正文但表格仍读取坏PDF文本层，关闭单元格匹配的第二次本地实验也未解决；图像副本路径第三次恢复了正文与参数表，未检出残留坏映射。三次均为既有本地OCR服务，不是收费模型HTTP。最终20页、345块、191分块；74个公式节点仍为空占位，不据此宣称公式或数学推导已可靠识别。明确显示公式／上下标／表格须核对原件的告警。20页渲染像素等价核验后复用了该次真实转换结果，保留实际上游任务、提交哈希及恢复说明；不是第四次重新OCR的成绩。

同次索引只对完全相同的文本复用向量，保留每个块原有身份和位置；该文档191块为111种唯一文本，实际14次向量HTTP，未删除公式占位或合并原文。原件、旧解析、旧索引均保留。原始页面、三次转换、像素等价、失败与修复证据位于工作树data/new-doc-failures-20261022/；正式切换记录见接力说明。该例只说明明显乱码修复和文字问答可用，不是通用OCR准确率或数学建模语义认证。

既有模型small，8GB显卡；medium只做过隔离验证。保留旧原件/解析/索引，本轮实验未覆盖正式结果。归一化与分块版本以源码及解析版本为准，不能把新分块代码的能力回填给旧解析。

## 量化与升级标准

| 维度 | 度量与出口 |
| --- | --- |
| 字符 | CER=替换+删除+插入/标注字符；只去空白，保留大小写、数字、标点、单位、否定。排印目标≤2%，真实扫描≤5%。 |
| 关键内容 | 编号、金额、日期、单位、限制等逐项计数；目标≥99%，不新增关键错误。 |
| 阅读顺序 | 使用实际输出树的先后关系，缺失或交错失败；目标≥98%。物理行拼接不算顺序恢复。 |
| 表格 | 值、行列起止、合并跨度、表头属性同时正确；目标≥98%，分原生/扫描报告。空白不是0。 |
| 成本与资源 | 设备总显存≤6.5GiB；完整候选耗时≤基线两倍，包含所有实际阶段。缓存回放不当成推理提速。 |
| 默认切换 | 保留CER相对下降≥20%，上述维度均过关且无待复核分歧；没有新保留验收不能自动升级。 |

CER只覆盖明确转录区域；表格正文另计，不宣称全文字符准确率。数据按原文档/模板分组，退化派生图不能跨组。公开来源是否进入模型训练未知，实施者可见保留不称独立盲测。完整原门槛和冻结文本逐字保留在归档。

## 用户PDF批的实际收益与失败

同一5页保留，最终统一标注口径下，全PDF CER25.00%、全IMAGE9.38%、按页面分流2.40%。v1开发发现扫描表单PDF路径仅5行、622/662编辑错误，图像路径28行；在任何保留推理前冻结v2分流。IMAGE内部会再次按scale渲染，两条路径有效OCR像素不同，尚未做等像素消融。

原生决算表开发109/215、115/120，经完整网格/表头候选后215/215、120/120；保留集没有规则表格，不能称跨文档表格通过。扫描课程表仍4/10格严格正确，开发总体339/345会掩盖这一失败。

补检v2因细行框/字符框去重不足新增重复，保留20→81/832编辑错误。v3双向覆盖离线回放恢复20/832，没有额外CER收益；新区域/分歧待原图核对，不发布为正式RAG事实。使用过该保留定位，v3只算修复回归。箭头与图形关系未建模。

放大原始嵌入图复核发现两处gold错误：少数股东段多写“的”，表单编号707281A应为T07281A；所有策略统一重评，原gold及两版勘误保留。JPEG重新编码绕过精确像素哈希，近似比对发现包装测试PDF第3页为旧注册表，但本轮实际选第4页。最终只用gold-reviewed/score-reviewed，不把标注勘误算模型提升。

该批36整页转换+36局部OCR，供应商0；设备峰值4.30GiB。推理阶段中位累计约1.49倍，但未含初次PDF渲染/host网格提取，完整无缓存性能未验。最新审查又修复缓存、候选文档树、空计划/部分成功与评估范围问题，见[阶段05](阶段05-代码审查与加固.md)；没有据此新增OCR成绩。

## 复现与后续

`scripts/run_ocr_profile.py`、`run_ocr_layout.py`、`run_ocr_pdf_benchmark.py`为隔离工具；有计划模式的入口默认不加载模型，显式execute才执行。推理容器网络none、模型/输入只读、不挂gold，不接正式库。代码变更后旧冻结脚本应使用原源码快照，不能用新实现冒充旧版本。

下一步优先扫描表格学段/符号/长格漏字、细框覆盖与漏检、阅读顺序、渲染尺度消融，以及不同来源规则表和中文困难扫描新保留。关键标注在推理前用原始像素独立复核。旧GPU启动、退出和worker恢复历史在本地整理前阶段原文及原data目录保留，不据此保证当前服务ready。


## 2026-10-23：PDF内联数字的受控归位

新增pdf-inline-verified-v1与docqa-normalized-8：独立数字节点、同页同栏坐标和原PDF文字层全文对照一致，且正文只缺这些数字时才恢复；不猜测数字归属、不替换OCR错字。独立节点与原件保留并注明来源，归入正文的碎片不重复进入索引。收稿日期及带机构序号的作者行不再当作论证章节，分块版本升为structured-heading-table-v5。

职教教师论文缓存规范化演练恢复3个内联数字，2023及72.3%与解释正文重新结合；4个疑似碎片仍未确认、保留原状及告警。新版61块，相同输入可复用旧向量，仅5种新文本需一批嵌入。repair_cached_pdf_layout.py默认只读规划，显式应用只产生新解析版本，零OCR/模型请求；幂等重规划与合成PDF端到端用例通过，旧解析及索引历史保留。schema14无迁移，正式切换以下述接力记录与发布核验为准。
