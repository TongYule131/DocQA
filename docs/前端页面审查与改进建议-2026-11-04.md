# 前端页面审查与改进建议（2026-11-04）

> 范围：`app/web/` 全部页面（客户端问答、管理端、登录/初始化/账号页）的只读代码审查。
> 性质：问题清单 + 改进建议，**未修改任何代码**。修复实施前需逐批确认，验证方式为定向回归 + 浏览器走查（本地全量回归按策略需单独授权）。

## 0. 总体结论

- 服务运行正常：web（8000 端口）、parse-worker、analysis-worker 三角色 ready，schema 19/19 一致；未登录访问受保护页面正确 303 重定向，`/docs` 团队模式 401。
- 安全面良好：全端无一处 `innerHTML`/`insertAdjacentHTML` 注入点，动态内容均走 `textContent`/DOM API；CSRF 由 `auth-bridge.js` 统一注入，凭证仅 HttpOnly cookie；上传/解析/索引有幂等键。
- 主要缺口集中在三块：**少量真实 bug（泄漏/状态不一致/崩溃）**、**CSS 级联体系失序（死规则+断点不统一）**、**交互一致性与兜底（三页同功能实现各异）**。

## 4. 缺口分析（根因）

1. **CSS 无单一事实源**：多轮迭代按"后加载覆盖"打补丁，产生大面积死规则与顺序敏感依赖；缺 CSS 变量与分层约定。
2. **三页平行实现未收敛**：unified-chat / conversation / workspace 的发送、签名、IME、清空逻辑各写一份，后改的页未回同步。
3. **轮询/异步生命周期处理不统一**：有的页面处理了 visibilitychange、有的没有；错误清理、busy 标志、失败回滚三件套各页齐全度不一。
4. **缺前端走查基线**：问题多为"单看每处都合理、合起来互相打架"，建议将本次清单修复后固化为一次全页面走查 checklist，纳入定向回归配套步骤。
