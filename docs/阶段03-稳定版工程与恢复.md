## 数据与版本不变量

正式数据目录必须显式指定，测试／预览／故障演练使用独立目录和端口。N01～N04正式更新后代码与运行均为schema17，实际发布时点及核验见阶段05；迁移登记须连续、结构匹配，旧库升级须先备份、演练并明确允许。未来库、损坏结构或不匹配代码拒绝启动；SkipMigrationCheck不绕过保护。

原件、解析版本、分块／来源、成功索引和历史结果绑定身份保存。新失败不覆盖旧成功；配置、输入或授权改变不能伪造旧快照继续执行。数据库、原件、头像、配置、模型证据和账本有不同保全范围。

## Windows启停与状态

```powershell
powershell -NoProfile -File scripts\start_local.ps1 -DataDir D:\python\DocQA\data -Port 8000
powershell -NoProfile -File scripts\status_local.ps1 -DataDir D:\python\DocQA\data -AsJson
powershell -NoProfile -File scripts\stop_local.ps1 -DataDir D:\python\DocQA\data
```

也支持pwsh。启动前核对目录、端口、schema和源码指纹，先Web就绪再启动解析／分析worker；端口冲突只报告。脚本不启动Docling，不自动迁移未知库或探测模型。

状态只读取web／parse-worker／analysis-worker三个角色文件。备份、重启窗口和监管器元数据不是角色。无效JSON、角色／PID／目录类型异常要显示错误并保留，不能拖垮其他角色查询，也不能伪报ready。就绪同时要求数据目录、代码、schema、PID路径及创建时间吻合；存活PID不等于本服务。

停机先给本目录监管器设置手停标记，再停止已确认的自身进程。遇到损坏记录仍继续处理其他可确认角色，保留未知记录、不杀未知进程，并以非零退出码说明停机仅部分确认。已有手停标记、费用与重启历史不清空。损坏记录须人工核对，不用删除ready文件绕过生命周期锁。

## 登录驻留

```powershell
powershell -NoProfile -File scripts\install_resident.ps1 -DataDir D:\python\DocQA\data -Port 8000 -DryRun
# 明确安装时去掉DryRun；已部署实例沿用原任务，不重复注册。
```

驻留为当前登录用户的Interactive／Limited计划任务，单实例、故障退避及重启窗口持久化。不能由PID存在推断健康；监管器不迁移库、不重发未知请求。停止优先于恢复，维护锁阻止启动／清理互相接管。真实注销登录和关闭Codex跨会话仍按任务书待验，不承诺无人登录启动。

2026-10-29发布恢复确认：现有计划任务保留DisallowStartIfOnBatteries及StopIfGoingOnBatteries默认条件，电池供电时可能排队或停止。本次按需运行后用户接回电源，原任务Running、监管器及三角色ready；任务定义未改。该限制见[LEG-008](项目遗留问题.md)，不声称已验证电池供电或真实跨注销登录的持续运行。

## 备份与隔离恢复

先检查在途任务并停止本目录监管器及全部角色。备份、恢复、清理与角色共用生命周期／维护互斥；不能一边运行一边复制裸SQLite主文件。

```powershell
.venv\Scripts\python.exe -X utf8 -m app.data_backup backup --source D:\python\DocQA\data --destination D:\DocQA-backups\backup-new
.venv\Scripts\python.exe -X utf8 -m app.data_backup restore --source D:\DocQA-backups\backup-new --destination D:\DocQA-restores\verify-new
```

目标必须是新的目录；备份不能位于源目录内部。SQLite backup包含已提交WAL数据，文件逐个核验并检测源变化。恢复核验实际落盘字节及schema／完整性；中途失败保留incomplete标记，不启动服务或覆盖旧目录。备份可只读支持历史schema，清理和启动仍须当前匹配结构。

模块备份数据目录时排除运行锁／db-backups等控制项，服务器`.env`和Docling模型缓存不包含在业务库内，须另行保全。历次发布的受控业务备份范围是DB、uploads、parse-results和独立配置／源码；不能将其称为包含整个历史实验data目录。

回退先保全发布后的新会话、资产、费用和墓碑，再恢复匹配源码／配置／schema的备份到新目录验证。不得拿旧库覆盖新增业务或遗留WAL，不用旧源码直接启动新库。

## 页面与静态资源版本

导航修复的验证／正式发布状态只见阶段05。页面与业务API始终no-store，页面重新读取时指向`/static/<实际运行源码指纹>/`；同版本公开JS／CSS及相对模块依赖可复用immutable缓存。个人头像、原件、正文、权限和CSRF不进入该资源目录。无版本／旧查询版本资源及缺失资源不获得immutable缓存；旧指纹目录不冒充当前版本。

正式更新仍先停机、保全新增数据、备份并验证隔离恢复，再更新源码和恢复三个同版角色；缓存不能代替这套流程。普通刷新读取新页面即可选择新资源，无需以清空全部浏览器存储为发布步骤。源码与真实SQLite结构检查继续执行，阻塞IO由线程池承担；服务端每次业务请求仍检查会话和权限，不能为了加载流畅跳过版本拒绝或认证。

## 临时内容清理

临时资料到期／移除先阻断访问与后续执行，物理清理为明确的停机维护操作：

```powershell
.venv\Scripts\python.exe -X utf8 -m app.attachment_maintenance --data-dir D:\python\DocQA\data
```

清理前确认库存在、schema匹配且生命周期锁可独占；错误目录不能生成新空库。文件目标必须在当前uploads／parse-results内，拒绝链接或越界；不把正式原件当成临时资料自动清掉。

旧附件和新临时库都要清结果／检查点、流式草稿、私有分享／案例正文、已确认澄清值、相关记忆和解析正文；确认／请求键、任务与费用墓碑保留，不能据清理重置账本或自动重试。备份历史、调用历史和正式资料不随清理删除；不承诺物理安全擦除。

## 容量与观测的已测边界

以下沿用原`data/s2-s5-closure-20261025/capacity-1024-4/report.json`口径，不是本轮新性能测试：

| 范围 | 实际结论 |
| --- | --- |
| 配置 | 1024维、4文档、32MB缓存 |
| 1k块 | 10个读请求＋2个本地生成桩无锁错误，P95约1.74秒 |
| 5k／10k块 | 只测顺序冷暖，约3.27／6.53秒，不冒充并发P95 |
| 内存与未跑规模 | 实测峰值约247MB；50k／100k预检达到停止条件，未实际跑、未承诺支持 |

瓶颈主要在向量核验／解码与Python精确余弦。词面预构建、ANN、独立向量库等须有对应规模和收益证据；当前不因文档整理引入基础设施。日志轮转、用户／全局配额、等待和取消保持原任务契约；排队、检索、首块和最终耗时分开统计，不把混合任务的P95当问答延迟。
