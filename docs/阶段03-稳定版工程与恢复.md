## 启停和状态

详尽命令只维护在[项目README](../README.md)。三个角色为Web、parse-worker、analysis-worker；Docling是独立Docker服务。使用相同DOCQA_DATA_DIR，状态须同时核对running、identity_match、data_dir_match、ready、code_match、schema_match。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/status_local.ps1 -DataDir data
powershell -ExecutionPolicy Bypass -File scripts/start_local.ps1 -DataDir data -Port 8000 -DryRun
```

正式旧库启动前先检查schema；只有已决定升级目标库时才使用AllowDatabaseUpgrade。源码变化会使旧Web返回503、旧worker拒绝后续处理，需按标准入口整体重启。只检查Web或Docker健康不能说明worker已ready。

脚本只停止身份仍匹配的本项目进程；端口冲突不杀其他服务。后台窗口隐藏。启动不创建业务任务，但旧排队任务可能被worker执行；先核对队列。前期审查未启停正式服务；后续用户明确要求切换后，已按上述记录重启三个正式角色，Docker保持。

## 恢复观察点

- 解析已保存上游task_id时恢复轮询；提交不确定且无ID时needs_attention，不重新上传。
- 分析/问答已校验检查点复用；存在未结算调用意图则不自动再发，明确retry保留调用历史和预算。
- 取消running只阻止后续步骤和发布，不承诺上游退款或停算。
- 结果、引用、版本、请求计数在重启后相同；读取旧结果与导出不生成。

离线演练可用 `scripts/seed_recovery_sample.py` 在新的独立data目录创建合成TXT/固定模型结果，再以同一目录启动/停止；不得拿正式默认库做故障演练。完整命令和原故障日志留在整理前阶段原文。
