# 阶段02：检索与问答

## 当前能力与接口

单文档、单轮、非流式。当前任务式问答源码为rag-task-v29、hybrid-context-v5、fact-context-parts-v7，抽取/复核策略为extractive-passages-v5与claim-support-rules-v4；旧同步rag-qa-v6接口和输出字段保留。真实各版成绩单独见阶段04；支持answered、partial、clarification_needed、insufficient_evidence。无依据与调用失败分别表达，缺项不能伪装成完整回答。

| 接口 | 行为 |
| --- | --- |
| POST `/api/documents/{id}/question-jobs` | 本地创建/复用持久化任务，必填问题和幂等键；不在HTTP提交中调用模型。 |
| GET任务、结果、列表/历史及导出 | 只读，不产生查询向量或生成。 |
| 明确retry/cancel | 保留累计预算和历史；不确定在途调用不自动重发，取消不保证上游停止计费。 |
| 旧POST `/questions` | 同步兼容路径；不能套用新任务的幂等、历史和恢复保证。 |

analysis-worker轮换问答与摘要/提取，不增加第四个本地角色。任务固定文档、解析、索引、输入和配置指纹；新活动版本不混入旧快照。用户主动重建索引或新建任务，不自动改写旧成功结果。

## 检索和上下文

默认8条向量初选，混合策略加入本地关键词、子问覆盖、章节与邻接证据；候选及实际输入受配置上界和字符预算控制。真实余弦分数保留，规则融合只影响顺序，不代表正确率。文档顺序恢复后重分配引用编号，缺失或重复顺序有明确回退。

v3在相同候选/字符预算内，优先保护问题点名概念的直接定义、明确指定章节的各小节正文，以及观点/主张判断所需的真实结论段。线索来自问题、原文和已有章节，不按文件名、页码或黄金答案分支；不生成分类轴事实标签，不增加查询或模型调用。代表段入选不等于章节已完整覆盖。

v4增加问题/真实来源槽位：比较题中用户点名的案例、明确章节/小节及作者结论。先为每槽轮换装入第一条，再补第二条及其他候选；候选池也预留这些来源，避免只在原排名末尾补入却已超限。最多16个槽位，仅为确定性检索线索，不保证“最短充分支持”或语义覆盖；预算/条数导致空槽时明确记录。事实题不强造多跳槽位。

任务式问答独立默认资料24000字符、总输入32000字符、装入32块、混合候选64块。对应配置`DOCQA_QUESTION_CONTEXT_MAX_CHARS`、`DOCQA_QUESTION_INPUT_MAX_CHARS`、`DOCQA_QUESTION_CONTEXT_K`、`DOCQA_QUESTION_CANDIDATE_K`；可继续扩大，块数须满足1≤装入≤候选≤100，资料小于总输入。向量初选仍8条，不因此增加embedding请求。`GET /api/rag/status`的task_question返回实际配置。配置签名冻结四项，排队后改预算会在外调前拒绝旧快照，不能静默扩容。旧同步和分析预算保持各自设置。

正文按实际问题抽取连续原句，表格保留整块原文、表头、注释和限定；预算丢弃内容不能引用，也不能称“全文没有”。可靠结构允许时可附表格行列辅助证据，但不挤走原文；结构提示不等于自动语义证明。恢复检索检查点逐项核对原文、来源、分块类型和顺序，元数据变化时在生成前停止。

v5对用户明确指定的小节补充真实正文候选，再在槽位第一/第二条之后装入其他槽位正文，优先于宽泛排名。抽取保留原文句子及指代、条件和例外的相邻依赖；只限制模型可见范围，库中的完整分块不改。题型决定单片段软目标（事实900、多跳700、辨析650字符），完整长句/依赖允许超目标；建议条数仅供诊断，不能硬截为5/12/8导致关键证据丢失。真正上界仍为配置的块数和实际JSON字符预算。全文路由不做抽取后冒充完整阅读，表格保持原文表头、单位、空白/0和注释。

同文档、版本、章节且顺序相邻的未完句保留两个独立范围；关联块共同装入，逐事实必须共同引用实际使用的续句。句号后空格、引号及文献标号不误当续句；不按页号自动拼接，也不合成一条跨页quote。原窗口/小段编号保持，省略编号形成缺口，不能跨缺口引用；重复窗口范围不反复消耗正文预算。未实现原始PDF逐字符坐标消重。

## 生成与引用契约

规则在system，问题/文件名/正文/元数据均为不可信数据。模型不输出文件路径、坐标或版本身份；服务端绑定真实来源。每事实由服务器从所选证据单元计算自己的refs，数字保留主体、期间、单位、范围和条件；共同论断需要共同证据。

服务器提供≤600字符的连续原文窗口和≤60字符的小段编号。历史v4由模型选择小段起止，v5改为只选1～8个预先公布的`{ref,unit}`原文单位；v7进一步在生成前将真实跨页未完句的各页范围声明在同一选项内，选择后服务器按该选项展开各页独立引文，并计算本条refs。跨窗单位须完整选择，不接受自行截取、隐藏单位或旧范围字段。各事实声明direct/synthesis/inference；共同范围只保存一次，v7总计不超过80个不同实际范围，每事实展开不超过48段；旧协议保留原上限。服务器回取原文、重分配展示引用号，并绑定稳定evidence_ids。模型不能填写证据ID、偏移、页码或坐标。

稳定证据ID绑定文档、不可变解析版本、分块、原文起止位置和quote哈希，不包含检索排名、索引或答案ID；在同一解析版本内重排不变，重解析后区分版本。范围为左闭右开Unicode码点，基于仅CRLF→LF的解析分块。相同短语的不同出现位置具有不同身份，不能用find静默选第一处。

拒绝坏JSON、重复键、未知字段、非法引用、越界/隐藏单位、小段伪造和过长输出；数值及context只能由本条实际选择的范围支持，不从同一窗口其他位置借用。仍守住总4000字符上限。新任务每事实恰为context/text/claim_type/evidence/part_ids五字段，refs由服务器生成。v6/v7用事实自身part_ids推导各子问的fact_indices，避免模型重复维护全局索引漏项。新任务缺少v7字段即失败，不降级；历史v1至v6继续读取和复核。原有离线裸调用默认v3，不把历史回放冒充新协议验收。章节/小节/页段定位、概念列举数与带版本的文字标识不强制填写测量context，但其中的数字仍须来自本条所选原文；人员、金额、期限、百分比等数值仍必须有实际限定。数值核对只统一明确三位分组（如1 000与1000），不合并任意OCR空格或容忍符号/真实数值变化，引用原字节不改。

原文精确匹配只证明身份和连续范围，semantic_status仍为not_reviewed；claim_type是模型声明，不证明归纳/推断正确。分类轴和否定子命题的完整性仍需语义复核；不能因数量相同强行对应，也不能凭局部未召回就断言全文不存在某关系。

新输入的quote_units预先列出连续证据段的窗口/小段组合及真实跨页关联范围，让模型只选已存在的原句单位；这是生成前的选项，不在生成后扩写失败引用。原文外围空白、引号和独立文献标号可不引，正文主语/谓语及条件仍不得截断。输出之后核对实际可见范围、句子完整性、本条跨页绑定和高精度推断标签；身份/范围违规受控失败，不自动重试。结构推断、全文缺失判断、关键称谓与否定方向风险另标needs_review，始终保留semantic_status=not_reviewed；词面规则不替代一般语义蕴含。

正文证据单元保留每个实际可见连续段，包含同段定义、解释和指代，避免只选“这样的评价过程”却不引前述定义；不会跨未读缺口合成原文。表格仍按独立行/句选择，以免混入无关值或脚注。段内原文较单句长，不能宣称始终是语义上的最短充分引文。

support_review随事实保存在已有结果JSON中，页面/历史/Markdown/JSON保留规则检查及语义待复核状态。恢复发布从真实冻结分块重算抽取范围与复核结果，拒绝检查点扩大范围、改标签或伪造通过；旧结果不回填新认证。新策略缺失或未知时生成前失败，不能静默降级。

子问状态、事实索引、缺项和整体状态需一致；partial列实际缺项，普通比较不强加未要求的正式定义。页面、Markdown和JSON保留逐事实context及引用，安全转义模型/文件文字。任务式历史可重开，刷新不自动生成；没有跨文档会话记忆。

页面与导出展示论断性质、稳定证据ID、范围与校验边界。可零模型调用读取指定版本的真实分块，在解析文本内高亮所选连续范围；前端按Unicode码点而非UTF-16下标处理。PDF页码/坐标仍是分块的来源区域，尚不声称原始PDF逐字符坐标高亮。旧结果不在读取时补造新身份或复核状态。

## 评估标准和当前证据

| 维度 | 判定方法与边界 |
| --- | --- |
| 检索 | 必要联合证据组全部进入候选/模型输入才命中；开发实际输入覆盖目标≥90%。没有穷尽相关性标注时Precision为null。 |
| 抽取后覆盖 | 除块ID路径外，另核对黄金quote的全部字符是否确在可见范围中；压掉关键句不能计为输入命中。原整块标签和新增关键句开发标注分别报告，不能换标签掩盖失败。 |
| 引用 | 编号/版本/原文形式违规不发布；引用是否支持论断另逐事实复核。 |
| 忠实度 | 有充分原文支持/已复核事实；数字错用、条件反转等严重错误不能靠平均分放行。无事实的正确拒答为N/A，不增加事实分母。 |
| 相关与覆盖 | 预标注必要回答组覆盖目标≥90%，另查错误拒答、过度partial和无关内容。 |
| 延迟与成本 | 记录实际HTTP次数、token usage和耗时；未知为null。缓存检索不代表无缓存性能，金额未核实不估算。 |

不把CLEAR-RAG名称或0.75/0.70视为已核实的本项目通用认证门槛。10月19日v18在3份资料7题的必要证据/回答组26/26、事实支持/引用/条件48/48；这是实施者已知开发复核，不能外推全场景准确率。原三题总耗时约34～65秒，检索使用缓存，完整性能未验。
