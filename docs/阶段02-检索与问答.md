# 阶段02：检索与问答

范围：版本化索引、单文档RAG、引用校验、网页与语义专项。原工程任务书和两份报告已归档；后续真实验收统一见[阶段04](阶段04-真实语义验收与提取改进.md)，当前代码修复见[阶段05](阶段05-代码审查与加固.md)。

## 当前能力与契约

- 单文档、单轮、非流式问答；回答依据提问时固定的索引及解析版本，切换版本不会混入另一文档或新版本证据。
- 候选按真实分值排序、去重、整块预算装入，再分配连续引用编号。相似度不是正确率；被预算舍弃的片段不能引用。
- 状态分为 answered、clarification_needed、insufficient_evidence。原文不足时不猜测，条件不足时询问1～2个关键条件。
- 模型只输出严格JSON；后端拒绝未知字段、重复键、非法引用、漏引述及非连续原文。编号、文档、版本、页码和来源由服务端绑定。
- 页面只渲染已校验内容，HTML作为文本；引用可跳转原件或对应版本。忙碌时不重复提问，迟到响应不能覆盖新选择，刷新不自动重发。

索引构建使用独立候选和租约，完整向量保存后原子切换；失败保留旧索引。历史索引可检索，但应明确显示与当前预览不一致。问答不保存会话历史，不支持跨文档或多轮记忆。

## Prompt维护要点

规则放入system；问题、正文、文件名和元数据作为不可信数据封装，不执行其中指令。每条事实只依赖自身refs；共同论断保留全部必要引用，独立论断分别引用。用户经历不由文档引用背书，澄清只问缺失条件；补充说明不重复政策数字。

保留单位、条件、例外和冲突；没有最低字数要求。上传／解析时间不是资料更新时间，不能据此裁决冲突。检索未命中不等于全文不存在，也不承诺不存在的客服渠道。修改Prompt必须记录版本、原因、错误反例及实际复验，不能改judge或预期消除失败。用户原始Prompt示例与体检清单在本次原文备份中保留。
