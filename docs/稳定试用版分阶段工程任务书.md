## 1. 本阶段目标与范围

在现有本地单用户、单文档工作台上完成：

**上传并解析文档 → 提取数据／结论／观点或生成摘要 → 显示真实处理状态 → 保存带引用的结果 → 重启后查看、复制或导出结果。**

继续保留已有单文档问答。当前问答语义专项按用户决定延期，不以修复 S03 作为本阶段启动条件，也不能把延期写成验收通过。

本阶段“稳定试用版”指处理过程受控、版本一致、数据可恢复、结果可追溯，并通过本任务书规定的功能和质量验收；不承诺任意文档零错误，不等于面向公网的生产部署。

### 1.1 必做范围

- 单文档通用信息提取：数据、结论、观点三类，不做任意自定义字段模板。
- 单文档摘要：小文档直接处理；长文档按确定范围分批处理并汇总，保留覆盖范围及引用。
- 分析任务、过程检查点、已校验结果的持久化；结果绑定不可变解析版本。
- 分析页面、任务进度、历史结果、引用入口、复制及 Markdown／JSON 导出。
- Windows 本地启动与停止入口、服务状态说明、独立环境下的恢复演练。
- 离线工程测试、有限真实在线语义评估、真实浏览器验收及实施报告。

### 1.2 不做范围

不开发跨文档问答、多轮记忆、网站抓取、浏览器插件、联网搜索、多用户权限、公网部署、新模型供应商、新文档格式、图表语义识别、公式重算。暂不引入 Redis、Celery、专用向量数据库或前端框架重写。不重做 Docling/GPU 部署、不升级无关依赖。RAG 答案的历史保存也不在本阶段范围；本次持久化针对新增摘要与提取结果。

## 5. M1：共享任务、版本、协议与持久化

### 5.1 数据归属与迁移

- 新任务固定 `document_id`、`parse_version_id`、输入清单／哈希、任务类型、协议版本、Prompt 版本和模型配置指纹（不含密钥）。摘要与提取基于选定的**解析版本**，不要求 embedding 索引存在，也不自动创建索引。
- 默认使用任务提交时的当前预览解析版本；可显式选择该文档的历史有效版本。invalid 版本拒绝；无足够来源的 legacy 内容应明确限制或拒绝，不能补造来源。
- 独立保存分析任务、尝试、分批步骤及调用账本、已校验结果。不可复用解析任务表承载生成任务。可复用领取、租约与短事务模式，SQLite 中原子领取，禁止网络请求跨长写事务。
- 结果至少保存结果 ID、任务 ID、类型、版本标识、已校验结构、引用、覆盖范围、质量告警、模型与 Prompt 版本、生成时间和请求数。前端展现与导出均从已校验结构生成，不把原始模型 JSON 当成可信结果。
- 同版本同配置可显示或复用已有成功结果；重新生成必须由用户明确操作，产生新的结果版本。新尝试失败不得替换或删除已有成功结果。
- 迁移按代码当前版本增量推进，迁移前生成一致备份，失败停止启动并保留备份；保留文档、任务、解析版本、分块、来源、向量与活动指针。测试正常迁移、失败回滚及重复启动；实现报告给出旧表关键数据前后对照。

### 5.2 任务状态与恢复

建议顶层状态固定为 `queued`、`running`、`succeeded`、`failed`、`cancelled`、`needs_attention`；处理阶段另用字段表示规划、分批生成、汇总、校验、保存。

- queued 可被 worker 原子领取。租约续期、步骤落盘和最终发布都核对执行令牌，过期 worker 不得继续发下一次请求或覆盖结果。
- 每次外部请求前，先在短事务中预扣预算并写调用意图。保存已校验步骤后才标记该步骤完成。
- worker 重启时，queued 和确定尚未发出的步骤可继续；已校验步骤直接复用。存在“已标记发出但未保存结果”的调用时转 `needs_attention`，不自动重发；不能宣称供应商 exactly-once。
- 失败或 needs_attention 只允许用户明确重试，并显示可能重复计费。重试保留历史调用记录，复用已校验步骤，只使用该任务剩余预算；预算耗尽不能靠 retry 重置。
- 取消 queued 任务不发请求；取消 running 任务阻止后续步骤与成功发布。已在途请求可能继续产生费用，页面只承诺停止后续处理，不承诺供应商停止计费。
- 前端重复点击、两个并发 POST 及断线后重发都必须有服务端幂等机制。相同幂等键及相同有效载荷返回同一任务；同键不同载荷返回 409。返回已完成任务不重新生成。业务主动“重新生成”使用新键。
- 任务状态与内容覆盖分开记录。接口成功或任务结束不能自动代表覆盖完整；失败任务可显示已完成批次进度，但不得把中间草稿发布为正式全文结果。

### 5.3 API 与错误契约

以下作为本阶段默认契约，M0 冻结后同步写入类型、API 文档、页面与测试。若需调整路径，必须给出等价映射，不能仅实现半套。

| 接口 | 行为 |
| --- | --- |
| `POST /api/documents/{id}/analysis-plan` | 只做本地输入规划；返回版本、计划摘要、输入批次、请求数上界、限制与是否可执行；零外部调用 |
| `POST /api/documents/{id}/extract` | 接通原占位入口，创建／复用 extraction 任务；新建或进行中 202，幂等已完成 200 |
| `POST /api/documents/{id}/summary` | 接通原占位入口，创建／复用 summary 任务；状态同上 |
| `GET /api/analysis-jobs/{job_id}` | 状态、阶段、已完成／总步骤、预算、错误、结果入口，不返回模型原始正文 |
| `POST /api/analysis-jobs/{job_id}/retry` | 明确重试失败或待处理任务；预算不重置，保留成功步骤及失败记录 |
| `POST /api/analysis-jobs/{job_id}/cancel` | 取消后续处理，重复取消幂等；不承诺取消已在途计费 |
| `GET /api/documents/{id}/analysis-results?kind=...` | 该文档已校验结果历史，包含版本及是否历史结果 |
| `GET /api/analysis-results/{result_id}` | 返回持久化结果，核实结果归属，不接受任意路径 |
| `GET /api/analysis-results/{result_id}/export?format=markdown|json` | 导出已校验结果及必要来源信息；不导出凭证、思考或原始模型响应 |

请求只接受必要字段，如解析版本、计划指纹和幂等键；类型由 summary/extract 入口确定。拒绝未知字段，不允许前端提交 system、模型端点、证据正文或文件路径。计划变化（例如预览版本切换）不能静默扩大费用：创建时固定显式版本与计划指纹，不匹配返回 409 并要求重新展示计划。

错误保持现有 `detail` 字符串惯例，可追加稳定 `code`。不存在为 404；非法参数为 422；解析不可用、版本／幂等冲突为 409；缺配置为 503。任务运行后的上游或校验失败写入安全失败状态，不把查询任务返回 200 当作处理成功。原 `/questions`、`/search`、上传及解析契约保持不变。旧摘要／提取原为未接入占位，本阶段改为任务式响应，必须明确记录该契约变化并更新测试。

### 5.4 预算与输入规划

- 默认每个分析任务最多 **8 次生成尝试**，建议配置 `DOCQA_ANALYSIS_MAX_REQUESTS=8`，启动校验为有限正整数且设置合理上界；值是可调整的实施默认值，不是已存在配置。记录全部实际配置名。
- 输入规划按该解析版本的完整合格正文／表格清单确定批次，不使用 RAG 的 top-k 检索代替全文遍历。参考当前输入字符预算，system、schema、元数据、转义及原文均计入。
- 不截断表头、单位、脚注、例外、条件来装入预算。必须拆块时保持原文连续范围和真实来源；无法安全装入时，在调用前给出明确限制。
- 展示预计请求数或保守上界，不伪造金额。单批可直接出结果；多批提取优先确定性合并，摘要需要的汇总调用也计入上界。输入／输出上界与汇总树在调用前有可验证的规划，不能运行时无限增加批次。
- 超过任务请求预算或全文输入上限时提前拒绝并说明原因。第一版不提供“只处理前几块却叫全文”的降级，也不为绕过预算自动拆成多个收费任务。
- 覆盖字段至少区分总输入单元、成功处理单元、未处理单元及原因、排除的非正文单元。覆盖是“该解析版本可分析内容的处理覆盖”，不是 OCR 正确率或任意全文理解率。
- 不增设生成结果的模型自评调用，不为这些新功能额外调用 embedding。一次任务内计划中的多个生成步骤不等于自动重试，仍必须逐次计费记录。

## 6. M2：数据、结论、观点提取

### 6.1 输出要求

每项包含服务端 item_id、`kind`（data／conclusion／viewpoint）、简洁内容、引用及必要限定。建议数据项另设名称、数值文本、单位、时间／期间、对象、口径或条件；没有原文依据的可选字段为 null，并区分未提及与明确不适用，不默认 0。

- 数值保留原文精度、正负、区间、不等号及原单位；第一版不擅自单位换算、计算比例或推导新值。科学计数法／OCR 不可靠时附限制，不能猜数。
- 明确区分文档明确给出的结论与作者／受访者的观点，保留主体、否定、假设、样本范围和适用条件；不把意见写成已证实事实。允许“本文得出……”等有据概括，不新增原文之外的研究判断。
- 表格按行列标题、单位、脚注建立事实；缺公式缓存、不清晰内容不能补值。不同时间、主体或口径即使数值相同，也不能错误去重。
- 某类没有项目时返回空列表并给出相应状态；不得为凑齐三类编造内容。已覆盖输入但无可提取项是合法 `no_extractable_items`，与模型协议失败分开。
- 引述／引用规则覆盖主内容和所有非空事实字段；不能主句有引用、数值或时间字段另行编造。

### 6.2 引用与合并

服务端给本次实际输入的来源范围分配编号；分批模型只能引用自己收到的片段，不能引用同文档未送入该批的编号。模型不得提供文档／块／版本 ID、页码、坐标或路径。

每条事实 refs 非空；每个使用编号对应一条真实连续原文引述，仅允许 CRLF→LF，不删空格、改字符或拼接不连续文本来制造匹配。拒绝重复 JSON 键、未知字段、布尔／浮点引用编号、未知编号、缺引述、未使用引述、越界引用及不合规状态；不修补后当成功。

分批结果先校验再合并。采用确定性去重，保持来源、对象、时间及条件差异。来源编号合并必须显式映射，不把另一个批次的相同数字当成同一来源；跨文档、跨解析版本引用均拒绝。

设定并测试单条文字、引述、单批条目及总输出上限。超过上限受控失败，不能截掉尾部条目再宣称完整。不要只用字段存在或数字包含验证语义，语义正确性按第 11 节另验。

## 7. M3：摘要与长文档处理

1. 摘要包括主题概述、主要内容／结论和必要限制；结构随文档内容合理变化，不要求不存在的“研究方法”等模板字段。关键事实、数据和文档结论逐条有引用。
2. 小文档可一次完成；长文档按章节或确定批次生成已校验中间结果，再汇总。每批必须保留其覆盖单元及原文来源映射。
3. 中间摘要是模型派生内容，不可成为最终“原文来源”。汇总阶段保留可追溯链；提供其要使用的已校验条目及原文证据，最终事实引用必须在汇总阶段可见，并校验到原文连续子串。不能仅凭上一步摘要文字给最终内容背书。
4. 同一个短引述若不能支撑其挂接的全部论断，应选择足够的连续原文或拆分事实；严禁为装入汇总预算静默丢弃重要限定。多层汇总也受固定请求上界控制。
5. 重要例外、冲突、假设、有效期、未经审计说明不能为缩短摘要而丢失。材料之间无可判定的更新时间时保留冲突，不自行选择“最新版”。
6. 成功结果声明的是“基于该解析版本完整合格输入生成”。原件图片／公式未解析、OCR 限制等告警继续显示，不能宣称对原件所有信息均已覆盖。
7. 任一必需批次未完成、校验失败或预算耗尽，本次不发布正式完整摘要；保留已校验检查点供明确重试。旧成功摘要继续可读。
8. 无有效正文与上游输出错误分开处理；后者不得伪装成“文档没有主要内容”。

## 8. M4：页面、历史结果、来源与导出

- 文档可解析但没有 embedding 索引时，只要有合格解析版本且生成模型配置可用，摘要／提取应可用；问答仍沿用自己的索引前置条件。
- 用户先看到分析范围、解析版本、计划请求上界与已有结果，再明确发起生成。查看历史结果不弹出计费步骤、不自动刷新生成。
- 展示 queued／running 的真实阶段及已完成批次，不伪造模型 token 流。长任务允许切换文档，任务归属和请求序号防止迟到响应覆盖新选择。
- 刷新页面后从持久化任务／结果恢复显示；普通列表刷新不能清空正在查看的结果或触发重复任务。使用服务端幂等键处理提交与响应丢失。
- 新分析任务期间预览版本改变，结果仍绑定原版本；明确提示历史版本，保留新的预览，不混用两个版本的原文与来源。
- 每条来源可查看引用卡、对应解析版本与原件；PDF 采用真实页码，DOCX／XLSX／TXT 保留各自位置，不能伪造页码或声称已实现字符级高亮。
- 使用可信结构及 textContent 等安全渲染；模型／文件名／引述／导出文件名中的 HTML、路径或脚本只作为文本处理，不加载外部图片或执行链接。
- 支持复制可读内容及下载 Markdown／JSON；包括结果类型、解析版本、生成时间、关键引用和限制。Markdown 危险语法需要安全转义或文本化；导出不包含密钥、服务器私有路径、reasoning 或未校验原始响应。
- capabilities 的 summary／extraction 只有在对应完整功能真实接通后置 true；分别报告模型配置和 worker 状态，不把“已配置”当成“可连接”或“账号可用”。

## 9. M5：启动、停止与恢复

建议提供 `scripts/start_local.ps1`、`scripts/stop_local.ps1` 或等价入口，参数支持独立 data 目录与 Web 端口。先给出可复现的普通命令，脚本只封装这些已验证命令。

- 启动前核对 Python、数据目录、端口、服务角色；明确区分 Web、解析 worker、分析 worker 与 Docling。已有解析结果的摘要／提取／问答不应因 Docling 离线全部不可用。
- 优先复用已运行且确认属于该项目及配置的服务；端口被其他程序占用时报告冲突，不能盲目杀进程。
- 如提供 Docling 启动选项，只用现有 compose/GPU 参数、`--pull never` 与缓存；不自动安装 Docker、拉镜像或下载模型。分析启动不隐式触发解析或模型探测。
- 后台进程在 Windows 使用隐藏窗口并记录所属 PID、启动时间、可执行路径、角色、端口和 data 目录。stop 只处理由该入口创建且身份仍匹配的进程，不能终止其他任务的 Python／Docker 服务。
- worker 有受控退出；未完成任务按第 5 节恢复，不能用启动恢复偷发不确定调用。提供状态查看方式及脱敏日志位置。
- 在独立环境演练迁移备份、任务中断、结果持久化、重启查看与恢复。正式升级步骤写入文档，**本任务中不执行正式库升级**。
- 同步 README、配置样例和软件版本显示，修正与当前代码矛盾的状态／schema 说明；不随意更改历史报告的数据。

## 10. 离线验收矩阵

默认测试必须走真实生产编排、仓储、校验和路由，只在外部 HTTP／模型边界使用 mock；至少一个完整 API 测试使用真实 SDK + MockTransport。不要全部替换为伪 AnalysisService。测试各自使用临时目录，禁止读写正式数据或依赖真实密钥。

| 编号 | 必须验证的行为 |
| --- | --- |
| A01 基线 | 既有上传、解析、版本、索引、检索、RAG 与安全回归保留；占位断言按新契约更新但不删掉业务意图 |
| A02 迁移 | v2 数据升级、备份、失败回滚、重复启动；已有成功版本及索引不丢失 |
| A03 前置 | 空参、未知字段、无文档、无解析、invalid、历史版本归属错误、缺模型配置，不产生外部调用 |
| A04 不依赖索引 | 有效解析但无 embedding 配置／索引时，摘要与提取可以执行，查询 embedding 调用数为零 |
| A05 规划 | 实际输入消息长度受限，完整输入清单和汇总请求上界可信；超限提前拒绝，不静默只处理前几块 |
| A06 幂等 | 并发重复提交只产生一个任务；同键不同载荷 409；已完成任务重复提交不新增调用 |
| A07 领取 | 两个 worker 竞争只有一个有效执行者；过期令牌不能发后续步骤或发布结果 |
| A08 不确定调用 | 请求意图之后、落盘之前中断进入 needs_attention；重启、轮询、SDK 均不自动重发 |
| A09 检查点 | 已校验步骤复用；明确重试只做未完成部分；失败／重试不重置预算，旧结果保留 |
| A10 取消 | queued 取消零调用；running 取消不发后续步骤、不发布成功；重复取消行为一致 |
| A11 版本竞争 | 分批／汇总期间真实切换解析版本，新结果始终来自旧快照，原索引与新预览不受影响 |
| A12 原文引用 | 未输入编号、跨批编号误映射、跨文档／版本、伪造页码均不能放行 |
| A13 严格协议 | 重复键、坏 JSON、错误类型、未知字段、空引用、过长、改空格／数字的 quote 均拒绝；不清洗修补 |
| A14 提取数值 | 单位、时间、主体、负数／区间、不同口径与缺失字段正确；无缓存不当 0；超量不静默截断 |
| A15 提取语义边界 | 三类内容归属、观点主体、否定与条件保留；无项目状态与模型错误区分 |
| A16 摘要覆盖 | 完整输入各必需批次被处理；漏批、失败或输出不完整不能发布“全文摘要” |
| A17 汇总引用 | 最终引用回到原文，派生摘要不能伪装成原文；不可见证据不能用于最终引用 |
| A18 安全失败 | 超时、401、截断、校验失败仅返回稳定安全错误；HTTP／日志不含假密钥、路径、原始响应 |
| A19 请求预算 | 每次外部请求前计数，失败／不确定调用计数；多阶段、重试及在线脚本总预算均不可绕过 |
| A20 重启持久化 | 任务、结果、引用、版本、覆盖和预算跨重启保留；GET 结果不再生成 |
| A21 UI 状态 | 忙碌与错误恢复、切换文档、延迟响应、刷新与重开；服务端幂等与页面行为配合 |
| A22 UI 来源与安全 | 引用及历史版本入口可用；文件名／事实／引述中的 HTML 不执行、不加载外部资源 |
| A23 导出 | Markdown／JSON 与已校验结果一致，含引用与限制；无路径穿越、恶意文件名、原始响应泄露 |
| A24 服务入口 | 端口冲突不杀无关进程；仅停止自身服务；角色状态正确；Docling 离线不阻断已有解析分析 |
| A25 无隐藏调用 | 启动、刷新、状态、能力、规划、查看及导出零模型调用；新功能不自动建索引 |
| A26 配置 | 配置由实际 Settings 读取，非法数值被拒绝；model/endpoint/thinking 不被前端覆盖 |

A21～A24 涉及页面／进程行为的部分必须有真实浏览器或本地过程证据，不只搜索脚本是否含某个函数。模型 mock 测试只证明工程行为，不证明真实语义正确。

## 11. 新功能语义评估与在线预算

### 11.1 先制定预期

建立 `tests/fixtures/analysis/` 的固定案例，模型输出之前写定：case_id、文档／版本、问题或任务类型、输入范围、必须覆盖内容、不得输出事实、来源、预期状态与判断理由。至少覆盖下列 12 类，可一题覆盖多项，但逐项记录：

1. 单一明确数据及单位／时间；2. 表格年份列与脚注；3. 公式无缓存；4. 否定与例外；5. 附主体的观点；6. 文档没有某类可提取内容；7. 条款冲突及缺生效时间；8. 扫描 OCR 空格与来源；9. 多章节摘要覆盖；10. 长文档跨批／跨汇总；11. 文档、标题或文件名注入；12. 编号与引述合法但事实错误的负例。

正反例必须经过生产校验路径。保留至少三种形式校验可能接受的语义负例：错误数值、错挂来源、漏掉决定性例外。它们在语义评估中必须失败；不要给评估器加特判凑全绿。重要摘要点与提取项的预期清单可用于记录覆盖分子／分母，但词面匹配不等于语义正确，仍需逐条阅读核对。

### 11.2 在线最小批次

在离线通过且用户明确授权该阶段在线预算后执行。建议实施预算上限 **24 次外部请求**（包含生成、若确需的 embedding 与其他收费模型尝试），整个本阶段共享，不能每阶段或每次进程启动重置。旧 RAG 预算不适用。仅已有解析版本的新分析通常全是生成调用。

在首个请求前写入固定计划、用例清单、Prompt／代码指纹、每题调用上界和累计账本。失败不自动重试；有实质修复后才允许在剩余额度内显式复验，不反复请求直到成功。余额不足就停止在线并报告未验证项。重新运行脚本必须读取已有账本，不能换文件名绕过总上限。无授权时完成离线与 mock 浏览器验收，并将真实在线明确标为待验。

最小批次为下列 **8 项功能场景**，优先复用隔离副本中的已解析样本与索引，不重新 OCR；计划必须在 24 次内容纳，不能靠删除用例省额度后仍称“全部完成”。

| 场景 | 核对重点 |
| --- | --- |
| E1 PDF 提取 | 数字、单位、真实页码／来源 |
| E2 DOCX 提取 | 结论与观点主体、条件和例外 |
| E3 XLSX 提取 | 行列对应、期间、缺缓存不猜值 |
| E4 TXT 提取 | 文档注入、无对应类别不编造 |
| S1 扫描 PDF 摘要 | 引述保持 OCR 原文、重点与页码一致、告警保留 |
| S2 DOCX 摘要 | 主要条款与决定性例外覆盖 |
| S3 长 TXT 摘要 | 至少两输入批次与汇总，全部必需章节处理，原文引用链正确 |
| S4 XLSX 摘要 | 单位、脚注、表格适用范围与缺值限制 |

每项保存实际输入单元、计划与覆盖、原始最终模型正文（不含思考）、校验结果、最终响应、逐事实复核、耗时与请求数量。证据只存本地忽略目录；报告只放可公开的结果摘要、失败原因和相对证据路径。

### 11.3 判定与停止条件

- 新功能核心案例不得有未说明的事实编造、错引、数字错误、决定性例外丢失、注入服从或假称全文覆盖。出现时保留失败、分析原因；未解决即不得把该功能标为语义验收通过。
- 网络失败、预算不足、样本缺失和未执行都不能计入通过；分别报告工程、在线语义、浏览器及部署演练。
- 一轮通过也只代表该批次；不得宣称长期正确率。记录真实分子／分母和证据，不把 RAG 延期项与新功能通过数合并。
- Codex 独立验收先审代码、预期、原始证据与离线结果，再决定必要复验。独立在线预算须单独由用户授权，不继承 DeepSeek 未用额度，也不默认重跑全部历史付费测试。
