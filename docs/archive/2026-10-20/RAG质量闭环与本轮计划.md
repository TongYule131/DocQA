# RAG质量闭环与本轮计划

日期：2026-10-18。状态：冻结评估后已实施离线改进；实际证据与首次失败在 `data/rag-quality-20261018/`，当前结果见接力说明及阶段04／05。以用户本轮“先建立评估，再针对性优化”及[整体提升方案](整体能力提升方案.md)为范围依据。

## 改动前冻结的标准

本轮按引用、延迟与成本、证据忠实度、答案相关性、检索五个维度分别记录，不合成一个掩盖严重错误的总分。未找到可核实的CLEAR-RAG原始定义，不将该名称当作已验证标准。0.75／0.70以及重排提升15%不作为本项目通用门槛。

| 维度 | 度量及边界 | 本轮出口 |
| --- | --- | --- |
| 检索 | 必要证据点Recall@k：一个要点的某个完整证据组全部出现才命中；分别统计候选和实际输入。Precision@k只在相关性已穷尽标注时计算，未标注不当不相关。 | 开发回归实际输入必要证据覆盖≥90%，逐类报告，无已确认严重回归；真实样本与合成样本分别列出。 |
| 引用 | 来源编号／版本／原文匹配由生产校验检查；引用是否支持论断另由逐事实复核。 | 已发布引用形式违规0；不能将形式通过率叫事实正确率。 |
| 忠实度 | 有充分原文支持的事实数／已逐条复核事实数；另记数字、主体、期间、单位、条件及事实用途。 | 缺复核时为未验证；已复核必须保留严重错数、条件反转等失败，不以平均分放行。 |
| 相关性与完整性 | 已回答必要要点／预标注必要要点；另查无关回答、错误拒答、过度partial。 | 开发集必要要点覆盖目标≥90%；真实生成未执行时不能用检索覆盖代替。 |
| 延迟与成本 | 实测本地规划／证据构建耗时、输入字符数、实际HTTP次数及供应商usage；缺测或缺usage用null。 | 不增加隐式远端调用；缓存回放不能冒充新在线时延或费用。 |

证据组允许多个等价来源，但同组中的必要片段必须齐全。评估标签绑定文档、解析版本和完整分块哈希；人工复核绑定具体答案哈希。无标签、无响应、无复核分别记未验证；不给模型自评分冒充事实支持。

## 固定范围与对照

1. 保存修改前源码、配置、Prompt哈希、Git差异和原始失败；先完成离线基线，再修改应用代码。
2. 使用多份、不同主题的许可／合成材料，覆盖结构关系、多子问、阶段任务、数字条件、例外、表格、无答案和干扰内容；用户论文作为单列真实回归。标签在候选输出前冻结，不能看新结果修改预期凑通过。
3. 相同原文、查询向量／相似度、上下文字符和块数上限，对照旧策略与新策略。分别报告候选召回和实际输入召回，保留被预算舍弃的证据。
4. 保存人工完整证据输入清单，供下一轮在线对照：区分原文缺失、检索／装入不足与生成不足；完整输入清单不等于模型已正确回答。
5. 本轮不新增供应商请求，先复用保存的真实证据与离线回归。上一轮39/40账本保留，不为本阶段继承或重置额度；真实生成复验另行明确范围和累计预算。

## 本轮实现顺序

1. 增加默认离线的评估与质量关卡，输出逐题分子／分母、缺失证据、未验证项和源数据指纹。
2. 在现有混合检索上完善子问规划、按问题覆盖的本地重排、章节解释与邻接上下文，候选及实际输入均有确定上界。相似度不作为正确率；原始事实、余弦分值与来源不改写。
3. 更新任务式Prompt：按用户真正询问的要点回答，逐事实保留限定，不强求一一对应，不因缺定义而拒绝普通比较；旧同步协议继续兼容。
4. 修正OCR提示语义：区分一般准确性未验证、实际定位到的解析异常、图片语义未解析；不清除旧版本原始告警。
5. 运行受影响回归与全量工程验证，更新阶段记录；只有执行过的真实生成才给新Prompt语义结论。

图表视觉理解先保留明确能力边界与可复核原图区域。本轮不引入新视觉供应商、图谱平台、逐块LLM上下文生成或远端重排；后续是否增加由证据缺失类型及对照收益决定。已有结构分块不为满足通用建议强制增加固定10%～15%重叠，避免表格、条件及原文来源遭到破坏。
