# Docling 接入工程任务书

编写日期：2026-09-23。执行方：DeepSeek；完成后交由 Codex 对照本文件独立验收。

## 1. 任务目标与执行边界

在现有 DocQA 项目上实现下列完整链路：

**网页上传扫描 PDF → 创建持久化解析任务 → Docling 转换 → 保存结构化内容和来源 → 结构化分块 → 网页查看 → 用户主动建立 embedding 索引 → 检索并展示原文与来源。**

同时保留 UTF-8 TXT，接入 PDF、DOCX、XLSX。它们共用任务和结果管理，但 TXT 可以继续在本地解析，无须发送给 Docling。

这是开发任务，应实施代码、数据库迁移、测试和运行说明，不要只输出方案。按后文里程碑逐步完成，每步留下可检查的结果。新增和关键修改代码添加中文注释，重点解释状态转换、事务、重试、来源映射和兼容原因。

本阶段范围：

- 继续使用 FastAPI、SQLite、现有网页和现有 embedding 提供方。
- Docling 以现有独立 Docker 服务运行；业务 Python 环境只增加轻量客户端/格式检查依赖，不安装本地 Docling、PyTorch 或 OCR 模型。
- 保留已验证的 GPU 派生镜像与缓存卷。启动必须包含 `compose.ocr-gpu.yaml`，跳过 CPU，不重新下载镜像或清空缓存。
- 不实现 DeepSeek RAG 答案生成、摘要、提取、网站抓取、浏览器插件或多用户系统。这些未完成的能力继续明确返回未接入。
- 不更换前端框架，不引入 Redis/Celery、专用向量数据库等额外基础设施。
- 不擅自提交或推送 Git。保留当前已有未提交的验收文档修改，不覆盖或撤销。
- 不提交或输出 `.env`、真实密钥、业务数据库、上传原件、完整解析结果。测试和日志不得泄露密钥。

## 3. 固定的设计原则

### 3.1 将三个状态分开

分别表达：

1. **任务状态**：本次解析是否排队、执行、失败或完成。
2. **内容质量**：结构是否可用、有何告警、哪些内容不能作为可靠事实。
3. **索引状态**：哪个解析版本的向量可用，是否对应当前预览版本。

新任务失败不等于已有文档失效。不要用一个 `documents.status='failed'` 把旧内容和检索一起禁用。

### 3.2 版本不可混用

采用“不可变解析版本 + 版本内分块 + 版本关联索引”。建议 Document 同时保存：

- `active_parse_version_id`：当前预览使用的成功解析版本。
- `active_index_id`：当前可用的完整索引，索引自身绑定唯一解析版本。

本阶段约定：

| 场景 | 预览行为 | 检索行为 |
| --- | --- | --- |
| 第一次解析尚未成功 | 显示任务状态 | 不可检索 |
| A 已解析、已索引；B 正在重新解析 | 显示 A，可查看 B 任务状态 | 继续查询 A |
| B 解析失败或结构校验不通过 | 继续显示 A，并提示 B 的失败原因 | 继续查询 A |
| B 解析成功，尚未建立索引 | 默认预览 B | 可以继续查询 A，页面和响应明确标注“检索仍使用旧版本” |
| B 建索引失败 | 继续预览 B | A 的旧索引仍可用，不被失败尝试覆盖 |
| B 建索引成功 | 预览 B | 原子切换至 B 索引 |

查询必须读取所选索引绑定版本的原文，绝不能把 A 的向量与 B 的文本拼接。用户可查看检索命中的历史版本原文。提供方配置变化后旧索引仍按原规则判为不兼容，不得强行使用不同模型的向量。

这是防止数据丢失与来源错配的必做项，不是额外的历史版本管理产品；本期无须做删除历史、版本对比或自动清理。

### 3.3 成功状态不代表识别无误

- 保存 Docling 的任务状态与转换状态，分别判断。
- 上游 failure、partial_success、结果缺失或结构无效不得替换有效版本；可保存失败证据供诊断。
- 合法空白页允许保留，不因个别页面无文本拒绝整份文件。
- 整份文档无可索引内容时给出明确原因，不创建空的“成功索引”。
- 上游 success 仍可带质量告警，例如公式内容缺失、公式缓存缺失、图表未作语义解析。
- 不编造识别置信度，也不声称能够自动发现所有 OCR 错字或阅读顺序错误。

## 4. 工程包 A：结果契约与数据库迁移

### A1. 统一结构契约

定义独立于 Docling 响应的业务结构，至少包含：

| 结构 | 必须表达的信息 |
| --- | --- |
| ParseTask | 本地任务 ID、文档 ID、请求参数摘要/哈希、幂等键、任务状态、执行阶段、上游 task_id、尝试记录、租约/执行令牌、时间、错误码和安全错误说明 |
| ParseVersion | 版本 ID、文档 ID、原件哈希、解析器/版本、配置摘要、结果结构版本、质量状态与告警、结构化结果和 Markdown 位置、创建时间 |
| Block | 有序 ID、类型（标题/段落/表格等）、正文、标题路径、表格结构、一个或多个来源记录 |
| Chunk | 原有 ID、document_id、text，加解析版本、顺序、块类型、来源；兼容可空 page |
| SourceLocation | 格式类别、节点引用；PDF 页号/坐标/坐标系，DOCX 章节路径/表格行列，XLSX 工作表/单元格或范围，TXT 行范围 |
| QualityWarning | 稳定告警码、中文说明、严重程度和受影响来源；未知范围可以为文档级 |
| Index / IndexAttempt | 索引 ID、解析版本、模型签名、来源签名及其算法版本、维度、块数、成功索引与本次构建尝试分别记录 |

来源可以有多个：长段落、合并表格或跨页结构不能只保留第一个来源。不要把 DOCX/XLSX 的来源强制变成 PDF 页码。`page` 兼容字段允许为空；来源的格式和单位必须明确。

### A2. 表结构与约束

建议新增 `parse_tasks`、任务尝试记录、`parse_versions`、版本化索引及其构建记录，扩展 chunks/vectors 与 documents。可使用等价名称，但必须保证：

- 同一文档最多一个活动解析任务；数据库约束或原子领取实现，不能只依赖前端按钮。
- chunk 归属于唯一文档和解析版本；向量归属于唯一索引和 chunk。
- 同一版本分块顺序显式保存，不再只依赖 rowid。
- 标明每个外键和唯一约束；SQLite 外键校验在每个连接启用。
- 网络请求期间不得持有 SQLite 写事务。
- 结果大文件可放 `data/` 下版本目录，但必须先完整写入临时文件、原子改名，再在事务中发布数据库引用。写文件或提交失败时旧版本不变；未发布文件可保留待清理。

### A3. 无损迁移

使用有版本号的迁移机制，既支持空库，也支持当前旧库，重复运行不重复改写。SQLite 原生迁移或迁移工具均可，避免仅追加 CREATE TABLE 后假称迁移完成。

旧数据迁移要求：

- 保留文档 ID、原件、chunk ID/内容/页码、向量、维度、提供方签名和索引状态。
- 给旧内容建立 `legacy` 解析版本并关联现有索引；不重新 OCR、不调用 embedding。
- 原本有效的索引在相同配置下迁移后仍可检索。
- **特别处理签名兼容**：旧 `source_signature()` 哈希包含旧 Chunk 的字段。增加 source/version 等字段会改变 model_dump，从而让旧索引全部 stale。为签名定义算法版本，并保留旧算法验证，或用已验证的一致旧数据在迁移中安全转换；不得简单重算签名掩盖损坏。
- 索引不完整、向量损坏或模型不匹配的旧记录不能被迁移成“有效”。
- 旧 parsing/indexing 中断状态按明确迁移规则处理，不能在每次 Web 启动时把新 worker 正在执行的任务统一改成失败。
- 备份须使用 SQLite 一致性备份或停写后的复制，考虑 WAL；不能只复制运行中的主数据库文件。
- 迁移失败停止启动并保留原库/备份，不静默新建空数据库。写明恢复旧代码与备份的操作步骤。

交付：契约说明、迁移代码、旧库迁移测试。先完成这一步，再修改解析调用。

## 5. 工程包 B：Docling 客户端与文件识别

### B1. 独立客户端

建议 `app/docling_client.py`，通过配置和注入便于测试，负责提交、查询任务和取结果，不负责改业务表。

以当前固定版本的 OpenAPI 和已验证脚本为准，接口为：

- `POST /v1/convert/file/async`
- `GET /v1/status/poll/{task_id}`
- `GET /v1/result/{task_id}`

默认参数沿用验收：RapidOCR、`ch`、`do_ocr=true`、`force_ocr=false`、accurate 表格、JSON + Markdown、placeholder 图片。不默认启用远程 VLM、图片描述或公式增强。

要求：

- 区分连接超时、单次读取超时和整个任务等待期限；均为可校验配置，不能无限阻塞。
- POST 不自动重试；查询与领取结果可以有限重试及退避，必须受总期限限制。
- 持久化上游 task_id 后才继续轮询。保存的 ID 优先用于恢复，不重新上传。
- 同时检查任务与转换状态；`json_content` 支持当前实测对象形式，并覆盖字符串形式的兼容测试。
- 将网络错误、HTTP 错误、上游任务失败、结果过期/不存在和结果结构错误区分为稳定错误码。
- 禁用本地请求继承代理设置和任意重定向，服务地址只来自后端配置，不能由前端覆盖。不得发送 DeepSeek/embedding 密钥给 Docling。
- 当前默认地址 `http://127.0.0.1:5001`；验证 scheme、地址及无内嵌凭据等。若支持远程解析部署需显式后端配置，不能默认上传到外部解析服务。
- 生产直接使用 httpx 时在运行依赖中显式声明，而不是仅依赖 dev 或其他包的传递依赖；同步更新锁定文件并核对 Python 版本。

### B2. 上传识别

- 支持 `.pdf`、`.txt`、`.docx`、`.xlsx`。其余类型明确拒绝，不顺带宣称支持 `.doc`/`.xls`。
- 扩展名和客户端 MIME 不能单独决定类型：PDF 检查文件标识及结构，Office 检查 ZIP 中实际包类型，TXT 检查 UTF-8 和非空内容。
- 对扩展名与内容冲突返回明确错误；大小写扩展名兼容。损坏/加密文件返回可读错误。
- 检查 Office 包时限制解压总量和条目，不执行宏、外链或嵌入内容。
- 保留服务端随机 ID 存储原件；提交 multipart 时使用清理后的文件名和匹配 MIME，不能将无后缀存储路径当原文件名。
- 保留现有上传大小限制；应用限制不得超过已配置服务能力。页数超限须有明确失败状态，不能冒充完整成功。
- 上传与解析都不自动建立收费索引。

## 6. 工程包 C：持久化任务与独立 worker

建议增加 `app/parse_worker.py`，提供 `python -m app.parse_worker`。SQLite 是任务事实来源；Web 进程只接收任务与查询结果。

不能仅用 FastAPI BackgroundTasks、内存队列或线程变量承载任务。首期一个独立 worker 串行处理，仍要防止误启动第二个进程重复领取。

建议流程：

```text
queued → running（提交 → 等待上游 → 领取结果 → 规范化 → 分块 → 发布）
       → succeeded / failed
提交结果不确定 → needs_attention（保留恢复信息，禁止盲目自动重投）
```

要求：

- 使用数据库条件更新/事务原子领取，记录执行令牌、租约、心跳。续租和最终写入均校验令牌，过期 worker 不能覆盖新执行者。
- 重启后 queued 可继续；存在上游 task_id 的任务恢复查询/领取；网络短暂断开不立即丢弃上游任务。
- **提交不确定窗口**：上游已接收但 POST 响应丢失，或拿到响应后本地尚未保存即崩溃，可能没有可用 task_id。不能声称本地幂等键能保证上游 exactly-once；记录为待处理，只有用户明确重试才新建尝试，并提示可能重复转换。
- 上游任务丢失/过期时记录原因。容器重启不保证任务保留，模型缓存存在不等于任务存在。
- 同一结果重复领取、重复恢复或进程在“结果已落盘、尚未发布”阶段中断，不得生成重复的已发布版本/分块。
- 分块完成并校验后，在短事务中写版本、块和活动版本指针；发生异常不改变原活动版本及索引。
- 超时是本次等待超时，不代表远端一定停止；保存上游 ID，避免自动新建重复任务。
- 处理 SIGINT/退出时留下可恢复状态；心跳和轮询不会阻止进程在合理时间内退出。
- 重新解析明确由用户操作触发；不在启动、刷新或读取详情时自动重新解析。

文档级质量告警不必让任务失败；结果结构无效、上游部分成功等不允许发布。分别保存 `task.status` 和 `quality.status`，不要混为一个枚举。

## 7. 工程包 D：结构规范化与分块

建议新增 `app/document_normalizer.py`、`app/chunking.py`；名称可调整，避免把全部逻辑堆进 main.py。

### D1. 来源规范化

- 按 Docling 的 body/children 层级遍历阅读顺序，解析引用，不直接遍历 texts 后再追加 tables。避免把表格子文本和整表重复索引。
- 明确页眉页脚的处理规则；不要默默丢弃正文或注释。
- PDF 保存一基页号、原始 bbox、坐标原点/单位；空白页继续占原页号。
- DOCX 根据标题父子结构生成章节路径，表格保存表编号与行列；无真实页码时 `page=null`，不编造页号。
- XLSX 读取 sheet 分组名，将表来源网格起点与表内偏移组合为真实单元格坐标。当前样本第一表从 A2 开始，不能把表内第一行当工作表第一行。
- TXT 可以保留旧逻辑页兼容，同时新增行范围；说明其页码不是物理 PDF 页码。
- 来源节点绑定文档与解析版本，不能假设 Docling 的 self_ref 在重新解析后恒定。
- 未识别的关键结构类型或不合法来源必须显式告警/失败，不静默抛弃后标记完整成功。

### D2. 已知质量问题

- PDF `formula` 节点为空：保存其来源和 `formula_content_missing` 告警，不填补公式。
- XLSX 读取原文件公式及缓存（可使用只读 openpyxl，显式声明依赖）：保留表达式、缓存状态和单元格位置。缓存为空时标注 `formula_cache_missing`，不得当 0，也不得交由模型猜结果。
- 有缓存时也记录“文件保存的缓存”，不宣称已重新计算或一定最新；本期不启动 Excel/LibreOffice 自动重算。
- 表格的真实空白、跨行跨列合并占位、缺失公式值必须可区分。
- 已知扫描/复杂版式局限通过格式说明和文档级告警呈现；不把七份样本的具体错字写死到生产逻辑中充当检测。
- 目录点线可按明确上下文保守清理；全局删除点号、连字符或百分号不允许。
- 本期不修复 Docling 上游识别模型，也不承诺解决全部条款错序；必须保留核对原件的入口。

### D3. 分块规则

- 普通正文优先按标题与段落合并，设置可配置长度上限；长段落在句界或安全文本边界继续切分，保留准确来源，不产生仅重叠片段。
- 文本长度采用字符或 token 必须写明，不将字符数描述为 token 数；上限与 embedding 请求限制协调。
- 表格保留标题、单位、多层表头、合并单元格及注释，长表按行组分块，每块带必要表头/口径和行范围。
- 单行过长也必须有确定处理规则和来源，不能越过限制或悄悄截断。
- JSON 是主结构，Markdown 是展示/检索文本的一种派生形式，不能只保存 Markdown 再反推来源。
- 不同时索引同一表格的整表 Markdown、单元格子文本和另一个重复副本。
- 页码、章节、工作表信息必须进入检索返回结构；按需给 embedding 文本加入标题/表头上下文。

## 8. 工程包 E：接口与索引兼容

建议接口约定如下，实际名称若调整须同步前端、OpenAPI、测试和文档。

| 接口 | 行为 |
| --- | --- |
| `POST /api/documents` | 保留 201 文档响应，补识别格式，不自动收费 |
| `POST /api/documents/{id}/parse` | 接收 `force` 和幂等请求标识；新建/复用活动任务返回 202 与 task_id；已有有效结果且未 force 可返回 200 的明确复用结果 |
| `GET /api/parse-tasks/{task_id}` | 返回任务阶段、时间、告警、错误和可用结果版本 |
| `GET /api/documents/{id}` | 当前预览版本、当前可用索引版本、最近任务和质量状态 |
| `GET /api/documents/{id}/chunks?version_id=...` | 默认活动解析版本；可以读取属于该文档的历史命中版本；不允许串文档读取 |
| `GET /api/documents/{id}/content?version_id=...` | 受控返回预览内容、结构与来源；较大结果分页/按需读取，返回稳定契约 |
| `GET /api/documents/{id}/original` | 按数据库文档 ID 获取原件，不接受任意文件路径；PDF 可在浏览器查看，Office 可下载核对 |
| `GET/POST /api/documents/{id}/index` | 查询当前可用索引和构建尝试；新建索引时固定目标解析版本 |
| `POST /api/documents/{id}/search` | 使用当前可用索引，返回 index_id、parse_version_id、是否旧版本及每条来源 |

幂等性要求：同一幂等键及相同请求返回同一结果；同键不同请求返回冲突；同文档活动任务重复点击不产生多次上游提交。失败后明确重试须新建尝试，保留失败记录。不存在的文档/任务/版本返回 404；非法状态或冲突返回 409。

响应模型允许明确的 API 行为变更，但必须记录 `/parse` 从同步改为异步的迁移说明，不能维持旧测试假装兼容。文档列表、上传、TXT、模型配置与现有检索功能保持可用。

索引要求：

- 保留现有向量校验、批次顺序、维度检查和模型不匹配处理。
- 构建前固定解析版本；向量先进入候选索引，全部成功且状态核对后原子切换。失败不修改已有成功索引的可用状态。
- 建 B 索引期间若 C 成为活动解析版本，B 的构建不得悄悄成为“C 的索引”；本期采用发布前核对目标版本，变化时标记本次构建已过期并保留原活动索引。
- 同一版本同一模型重复建立时复用，不重复调用收费接口。
- 查询在一致快照中读取索引、对应版本分块和向量；正在切换时得到完整旧版或完整新版。
- 增加来源字段时同步修改 source_signature、SQL 查询、Chunk 构造和结果序列化，不能仅更新 Pydantic。
- 本阶段不强制把 embedding 建立也改成持久化队列，允许保留同步入口，但必须实现上述候选发布和失败保留机制。

## 9. 工程包 F：网页交互

继续使用现有网页，至少实现：

- 上传 PDF/TXT/DOCX/XLSX，显示实际格式及支持边界。
- “解析文档”“重新解析”明确区分；提交后显示排队/执行阶段/完成/失败，不让一个长请求阻塞整页。
- 每 2—3 秒查询任务；终态停止；临时断网显示连接状态并有限退避。没有真实总进度时不要显示虚构百分比。
- 刷新页面后从服务端恢复任务；切换文档时旧轮询响应不得覆盖新选中文档，清理旧定时器和过期请求。
- 重新解析期间可继续查看旧内容与检索；失败后同时显示新任务错误和“原有版本仍可用”。
- 当前预览和检索版本不同时明确提示，并支持查看命中的旧版本来源。
- 展示正文、表格及质量告警。PDF 显示页码并提供原件页跳转；DOCX 显示章节/表格；XLSX 显示工作表和单元格范围。精确框选高亮可后续做，本期必须保存 bbox。
- 原文、文件名、服务错误和 Markdown 均不可信；继续使用 textContent/安全 DOM，若引入 Markdown 渲染必须做 HTML 清理，不直接 innerHTML 注入。
- 扫描 PDF 标注 OCR 局限；公式空值不能显示成 0。
- 建索引和搜索继续由用户主动触发；页面加载、任务轮询、预览不能触发 embedding 或 DeepSeek。
- 更新 `/api/capabilities`，区分格式支持与服务可达；health 成功不表示模型已预热或内容质量合格。RAG 等未做功能继续 false。

## 11. 必须覆盖的自动测试

全部自动测试默认离线，使用临时目录/临时 SQLite、可注入客户端和模拟 embedding；不能依赖本机正在运行的 Docker、真实密钥或当前已有数据。不得通过删除测试、跳过关键断言或仅验证 HTTP 200 来掩盖回归。

| 编号 | 验收场景 | 必须证明 |
| --- | --- | --- |
| T01 | 当前旧库升级、再次启动 | 文档/块 ID/向量保留，相同配置仍能检索，无自动 API 调用 |
| T02 | 迁移中途异常 | 不发布半完成结构，备份可恢复，不建空库掩盖失败 |
| T03 | 重复 parse、并发 parse、幂等键冲突 | 一个活动任务，相同请求复用，冲突可识别 |
| T04 | 两个 worker 争抢/旧租约过期 | 单次领取有效，旧令牌不能写入或发布 |
| T05 | Web/worker 重启，上游 ID 已保存 | 恢复查询与领取，不重复 POST |
| T06 | POST 已接收但响应丢失 | 明确不确定状态，不自动重投，不声称 exactly-once |
| T07 | 上游 failure/partial_success/404/超时/错误 JSON | 错误分类正确，无效结果不发布，旧版不变 |
| T08 | 结果文件写入失败、分块失败、数据库提交失败 | 原活动版本和原索引仍可用 |
| T09 | 完整结果重复领取及提交前后中断 | 无重复发布，无重复分块，恢复结果可解释 |
| T10 | 空白页夹在正常页中、整份空文档 | 前者页码不位移，后者不生成虚假可用索引 |
| T11 | 标题/正文/表格交错、有表格子节点 | 阅读顺序正确且表格不重复索引 |
| T12 | PDF 多来源 bbox、DOCX 嵌套标题/合并表格 | 来源完整，DOCX 不伪造页码，跨度保留 |
| T13 | XLSX 多工作表、表从 B3 开始、合并格 | 工作表名与真实坐标正确，不只通过 A1 起始样本 |
| T14 | XLSX 无缓存/有缓存公式、真实空白和零 | 区分含义，无缓存有告警，不变成 0，原件未修改 |
| T15 | 超长正文/超长表/单行超长/中文数字 | 长度受控，表头单位注释随块，数值符号不损坏 |
| T16 | A 有索引，B 重解析失败/成功未索引 | 失败后 A 仍可检索；B 成功后预览与旧版检索明确区分 |
| T17 | B embedding 中途失败/成功 | 失败保留 A；成功全量原子切换至 B |
| T18 | B 建索引时 C 发布、查询与索引切换并发 | 不混版本，不发布过期目标为当前新索引 |
| T19 | 新来源字段与旧签名、模型或维度改变 | 旧有效签名兼容；真正不兼容仍拒绝 |
| T20 | 格式伪装、损坏/加密/超限、任意路径请求 | 受控拒绝，原件清理正确，不能串文档访问 |
| T21 | 前端刷新/切换/断网/重复点击 | 任务恢复，旧响应不覆盖新文档，定时器停止 |
| T22 | 文件名/正文含 HTML、敏感上游错误 | 页面不执行脚本，不泄露密钥/内部响应 |

T21/T22 可采用合适的浏览器自动化或可复核的浏览器实测；后端模拟不能替代真实前端行为。更改旧同步测试时要改为创建任务、执行可控 worker、查询结果的流程，保留原测试的业务意图。

## 12. 真实服务和人工验收

### 12.1 Docling 验证

在独立测试数据目录运行本次 Web 与 worker，连接本地已有 GPU 服务。至少复用：

- `04-scan-zh.pdf`：上传、异步解析、6 页来源及内容预览；识别缺陷仍如实提示。
- `05-mixed-text-scan.pdf`：各页有输出，页号不乱。
- `03-text-zh-tables.pdf`：第 12 页空白不拒绝，第 24 页表格来源可定位。
- `06-sample.docx`：章节、表格、合并信息和无伪造页码。
- `07-sample.xlsx`：3 工作表、实际单元格范围、B8:F8 的缺缓存告警。
- UTF-8 TXT：原功能回归。

可以使用上一轮 raw JSON 做适配器离线夹具，但这不能替代至少一条真实网页上传扫描 PDF 的完整链路。大体积原件/结果留在被忽略的数据目录；提交的测试夹具应小、可共享且不含密钥或私有资料。

### 12.2 索引与检索验证

先用模拟 embedding 完成端到端与故障路径。真实在线验证由用户在网页主动点击，或在已有授权覆盖的联调范围内使用现有配置执行；限定一份公开测试样本的一次必要索引和检索，不为测试自动调用所有文档，也不因接口失败无限重试。不要反复索要已经给予的授权。

真实验证需记录：样本名称、文档/任务/解析版本/索引 ID、实际检索问题、命中块、来源、与原件一致性。可以采用“本年鉴包含多少个部分”这类扫描样本原文能支持的问题。检索得到相关片段即可，本阶段不要求 DeepSeek 生成答案。

若尚未实际执行在线调用、缺少可用配置或服务不可达，必须标记“真实在线索引检索未验收”，不能用模拟 embedding 的成功替代最终完成标准。完成其他开发和离线验证后，给出用户可直接操作的网页验收步骤。

### 12.3 必须亲自复核的故障链路

以已有成功解析并建索引的 A 为起点：让重新解析 B 在可控测试环境失败，刷新页面，再检索 A。证明旧内容和旧索引依然**可用**，不能只展示数据库还有旧行。

恢复上游后重试 B、成功发布、建立新索引、检索并检查版本与来源，再重启 Web/worker 检查持久性。故障注入仅针对测试环境，不修改生产数据或破坏真实原件。

## 13. 交付清单

1. 实现代码、中文注释、依赖与锁定文件更新。
