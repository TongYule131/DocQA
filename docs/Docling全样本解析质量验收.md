# Docling 全样本解析质量验收

日期：2026-09-23。范围：独立解析服务的 7 份样本验收，不包含业务接入或 RAG 问答验收。

## 结论

**Docling + RapidOCR GPU 作为 DocQA 的解析服务可行，可以进入有明确格式边界的接入开发；本轮不能判定全部格式的内容质量通过。**

7 份文件均完成异步转换，任务与转换状态均为 `success`，接口 `errors` 均为空。但原件对照发现扫描目录页码错误、中文段落顺序错误、数学公式内容为空、Excel 无缓存公式静默变为空白。它们说明接口成功与内容可靠必须分别记录。

建议首期开放普通文字 PDF、DOCX 的正文检索；扫描及混合 PDF 提供试用和原件核对入口。复杂目录、公式和图表不能承诺准确还原。XLSX 需先补公式缓存检查、工作表来源和单元格定位，再开放正式入口。暂不扩展浏览器插件或网站抓取，先完成解析到引用的基础链路。

## 条件和证据

- 输入目录：`D:\python\DocQA-test-files`，实际 7 份文件。样本说明提到的第 8 份不在目录内。
- 结果目录：`data/docling-validation/20260923-110942-182134-gpu-seven-acceptance/`，已被 Git 忽略。
- 使用本地派生镜像 `docqa/docling-ocr-gpu:1.34.0-ort1.30.0`；Docling Serve 1.34.0、Docling 2.128.0、RapidOCR 3.9.2、ORT GPU 1.30.0。
- GPU 环境和服务内三模型执行证据沿用 [OCR GPU 验证报告](Docling-OCR-GPU验证报告.md)。本轮没有运行 CPU 基线或开启 profiling。
- 请求固定 `rapidocr`、`ocr_lang=ch`、`do_ocr=true`、`force_ocr=false`、`table_mode=accurate`，输出 JSON 与 Markdown。未开启公式增强或图片描述。
- 使用已有本地模型缓存启动服务，7 份样本串行转换，每份仅执行一次。以下耗时是本轮观察值，不是性能基准，不代表冷启动或并发能力。
- `summary.json` 保存文件 SHA256、任务 ID、时间和状态；`*.result.json` 保存服务原始响应；`*.structured.json`、`*.inspection.json` 便于检查结构；`source-audit.json` 和 `acceptance-checks.json` 保存原件对照结果；`service.log` 保存本轮服务日志。
- PDF 共 73 页，全部渲染为预览并核对页清单；重点页面进行视觉与文本/单元格对照。未逐字校对全部 PDF，未计算 OCR 字符准确率。DOCX 使用本机 Word 只读导出进行视觉核对：技能自带渲染器因缺少 LibreOffice 无法运行。XLSX 只读检查原始值、公式、缓存和合并区域，没有重算或改写文件。
- 7 份原件验收后 SHA256 与提交转换前一致。

复现转换命令（需要已启动含 OCR GPU 覆盖配置的解析服务）：

```powershell
.\.venv\Scripts\python.exe scripts/validate_docling.py D:\python\DocQA-test-files --label gpu-seven-acceptance --ocr-lang ch
```

转换脚本复现的是接口执行与证据保存；仍需按下文问题位置核对内容，不能用退出码替代质量验收。

## 可复核的内容检查

### 01 英文单栏 PDF

- 第 2 页确认是单栏，正文段落顺序抽查正常；标题与正文有结构标签。
- 第 8 页 Table 2 对应 `#/tables/1`：Transformer base 的 EN-DE / EN-FR 为 27.3 / 38.1；big 为 28.4 / 41.8，与原图一致。JSON 保留 BLEU、Training Cost 的跨列关系。
- 科学计数法被展平成如 `3 . 3 · 10 18`，不能保证指数语义可供模型直接准确理解。
- `#/texts/90`、`98`、`99`、`109`、`118`、`137` 的标签是 `formula`，文本为空。例如第 4 页 `#/texts/90`。这是实质内容缺失，不能标记为“全文完整”。
- 处理建议：保留公式位置，输出明确缺失告警；需要公式问答时再单独测试公式增强及其资源开销。[官方说明](https://docling-project.github.io/docling/usage/enrichments/#formula-understanding)将公式理解列为独立增强功能，本轮未验证它能否修复这些样本。

### 02 英文双栏 PDF

- 对照第 1 页，输出顺序为左栏摘要、左栏 Introduction，再接右栏 `There are two existing strategies...`，未出现逐行左右栏交错；第 1 页末句可接第 2 页。
- 第 6 页 Table 1 对应 `#/tables/0`，模型、任务列和训练样本数没有被拆成无关正文。抽查 BERT LARGE 行 MNLI 86.7/85.9、SST-2 94.9、Average 82.1，与原图一致。
- 表格 Average 82.1 与正文官方 GLUE 80.5 是不同口径，原文表注已说明；不能把两者不同算成解析错误。分块必须保留表注。
- 仍有 `fi ne-tuning`、`Weshow` 等排版/空格问题。首期可做正文检索，不能据两个重点页面宣称全篇精确还原。

### 03 中文表格 PDF

- 第 12 页视觉为空白，输出 `pages` 中保留该页，文本/表格/图片项数为 0。这是正常空白页，不应导致整份文件失败。
- 第 24 页表 2 对应 `#/tables/9`：全国、城市、农村三列对齐。9 行共 27 个数值视觉核对一致，例如交通通信 -1.9 / -2.0 / -1.5、医疗保健 1.3 / 1.2 / 1.5。标题中的年份与指标口径应与表格一并保留。
- **第 4 页错序**：`#/texts/25` 先输出“年及以后的数据…”及第七条前半段，`#/texts/26` 再输出“六、安州区、北川县 2008 未作机械调整…”。原件第六条本应连续，第七条的尾句也被接到第六条后。该问题存在于有文本层的页面，不能归咎于扫描 OCR。
- 第 5—11 页目录被识别成表格。点线引导符大量保留，Markdown 空格填充进一步放大文本；110079 字符不等于有效正文有这么多。
- 第 13—21 页多为统计图版。OCR 读出图中的标签和数字不代表已经建立系列、年份和数值的可靠对应关系；本轮不验收图表问答。

### 04 合成扫描 PDF

- 6 页均无文本层，分别是编委会、编者说明及四页目录；不是 6 页经营数据表。
- 第 1 页 `#/texts/0` 的标题把年份拆乱，多出数字；名单的一部分出现在“主任/副主任”前，姓名之间缺少可靠边界。不应据此准确回答“某人属于哪个职务”。
- 第 3 页 `#/tables/0`：原件“县市区行政区划和行政区域面积”对应目录页码 34，结果是 `3.4`；原件开头三个公报各有独立页码 1、17、25，解析后出现跨行合并，丢失独立对应关系。
- 第 2 页可读出主要说明；这不能抵消其他页的错误。扫描目录数字已经有反例，不能宣称数字识别通过。
- 此样本由电子稿加噪生成，没有真实装订阴影、透字、倾斜和拍照透视覆盖；也没有用于核对千分位、负数、百分比的扫描业务数据表。

### 05 混合 PDF

- 原件第 1、3、5 页无文本层，第 2、4、6 页有文本层；6 页输出都有可追溯的结构项。
- 第 2 页的 `#/texts/15`、`#/texts/16` 与 03 第 4 页有相同条款错序；第 3 页目录也有行合并、缺值问题。
- 输出 36360 字符，明显大于 04 的 9188 字符。检查发现文字目录页保留大量点线，Markdown 又填充空格；本轮 05 含 6206 个句点字符。**不能单凭长度推断 OCR 把整页提取了两遍。**
- 未发现整页双份输出；是否存在全部局部重复仍需更细的逐行基准，不能标为全面去重通过。

### 06 DOCX

- 原件正文 8 段全部可在结构化文本中找到；原表展开为 8 行 × 5 列，40 个位置与原件一致（比较时仅忽略空白）。
- 表标题 `col_span=5`；“区域”“营业收入”“净利润”各 `row_span=2`；“其中” `col_span=2`。结构化结果保留跨行跨列，Markdown 则重复展开表标题并失去合并外观。
- 有一个 Title 和三个同级 Heading 1。**样本没有 Heading 2/3 嵌套，不能据此验证任意多级标题树。**
- `pages={}`，16 个文本节点和 1 个表格的 `prov=[]`。可用标题父子关系、`self_ref`、表格行列定位，但不存在真实 Word 页码保证。
- 引用需同时绑定文档与解析版本，不能把 `#/tables/0` 视作跨次解析稳定 ID；不可为了兼容旧 `page:int` 随意填写“第 1 页”。

### 07 XLSX

- JSON 的三个 `sheet` 分组名分别为“分区域数据”“指标说明”“原始记录”。Markdown 没有这些工作表标签，因此仅保存 Markdown 会失去重要来源信息。
- 72 个非公式、有值的原始单元格，与结构化映射后的文本一致。`原始记录!B2` 的日期 2023-11-08、`C2` 的 1234.56 均保留。
- 第一张表范围为 A2:F8，表来源 `bbox` 为 `l=0,t=1,r=6,b=8`，属于零基单元格网格；结合表内偏移可还原 `分区域数据!B4`。**不能仅用表内行号加 1，也不能把这类 bbox 当 PDF 点坐标。** 这个映射在当前样本逐格验证，其他布局仍需回归样本。
- `B2:C2`、`D2:E2` 跨列信息存在，A1:F1 的标题作为独立文本保存。
- B8:F8 原始公式均为 SUM，缓存值均为空。结果中的 5 个位置都是空字符串，公式表达式没有保留，接口仍无错误。需要额外读取原文件的公式与缓存，生成“公式结果不可用”提示；不能按空白、0 或模型估计值入库。
- 本轮没有重算工作簿，也没有验证已有公式缓存的工作簿。[固定版本 Excel 后端源码](https://github.com/docling-project/docling/blob/v2.128.0/docling/backend/msexcel_backend.py)可作为后续定位行为的参考，验收结论以上述实测为准。

## 格式支持及已知限制

这里的“首期”是开发建议，不代表 DocQA 当前接口已开放这些能力。

| 格式 / 内容 | 首期建议 | 接入前需要落实 |
| --- | --- | --- |
| UTF-8 TXT | 保留原有支持 | 沿用当前路径；本轮样本未新增 TXT 验收 |
| 普通文字 PDF | 有条件支持 | 页码和结构来源、空白页处理、质量告警、正文顺序回归 |
| 双栏 PDF | 有条件支持 | 保留表注和阅读顺序；复杂页面支持原件核对 |
| DOCX | 有条件支持 | 用章节/表格来源，保留合并信息；补充嵌套标题真实样本 |
| 扫描 / 混合 PDF | 试用支持 | 显示 OCR 风险，保留页图位置；补真实扫描件及数值表验收 |
| XLSX | 完成适配后支持 | 工作表、坐标、公式和缓存缺失告警，不把页序伪装成页码 |
| PDF 数学公式、统计图表 | 暂不保证 | 单独评估增强模型，不把空公式或散乱图标签当可靠知识 |
| 旧 DOC/XLS、图片、PPTX、网页等 | 本轮未验收 | 不能因 Docling 支持某格式便直接对外承诺 |

本轮已经完成“7 份文件转换、逐格式原件对照、问题登记和支持边界判断”。未完成的是**全格式质量放行**。真实扫描件、扫描数值表、嵌套标题、跨页业务表、含缓存公式、损坏/加密/超限文件仍需补样本；其中后几项可以随接入开发完成，不必阻塞基础客户端与任务模型。

## 对下一阶段的具体调整

已有 `app/main.py` 同步解析、`app/parsing.py` 按 800 字符切块、`app/schemas.py` 强制页码、`app/repository.py` 直接替换分块并删除旧向量。这些设计需要一起调整，不能只替换一个解析函数。

1. **先确定统一结果契约和质量状态。** 区分任务执行状态、内容质量和索引状态。来源包括解析版本、节点 ID、PDF 页/框、DOCX 章节或表格、XLSX 工作表/范围；页码允许不适用。结构化 JSON 是主结果，Markdown 用于预览。
2. **再做持久化异步任务。** SQLite 保存本地任务、上游 task_id、尝试次数和最近错误；独立工作进程领取任务。POST 响应丢失时先核对状态，不盲目重复提交。Docling 的异步接口不能替代业务任务持久化，重启恢复另做测试。
3. **保留旧解析和索引版本。** 新结果写入候选版本，通过校验再切换；失败不删除旧分块和向量。新分块与向量必须绑定同一版本，不能让新文本配旧向量。数据库采用可验证的增量迁移，先用数据库副本验证保留旧数据。
4. **按结构分块并实现格式适配。** 正文附带标题路径，表格按行组切分并携带多层表头、单位、注释和来源。目录点线只在明确目录上下文清理，不能全局删除句点破坏小数。XLSX 的无缓存公式需要明确缺失标记；空公式、复杂目录等问题先告警或隔离，不能假装自动修复。
5. **最后接网页并做端到端验收。** 上传保留原件，显示排队/解析/带告警完成/失败及来源预览，再由用户触发已有索引流程。首个验收链路是“扫描 PDF 上传 → 异步解析 → 查看带来源结果及告警 → 建索引 → 检索”；带引用 DeepSeek 问答仍是后续独立阶段。

文件名扩展名和客户端 MIME 只作提示；上传侧需要结合文件签名、Office 包结构和解析器结果识别格式。现有上传原件以无后缀 ID 保存，提交 Docling 时必须携带经过清理的原文件名与正确媒体类型，不能拿存储路径推断格式。

下一阶段不需要再次证明同一个扫描样本使用 GPU，也不需要更换现有 DeepSeek / embedding 接口。优先实现结果契约、任务持久化、版本切换和可见的质量边界。
