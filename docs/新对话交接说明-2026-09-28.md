## 3. 已实现架构

FastAPI + SQLite + 原生网页工作台。原件上传后生成持久化解析任务，独立 worker 调用本机 Docling 服务，保存不可变解析版本、结构块、分块、来源和质量告警。在线 embedding 建立绑定解析版本的索引，检索后交给在线 DeepSeek 生成回答。

- 解析：Docling 独立 Docker 服务 + RapidOCR，已有 GPU 验证；显卡 RTX 4060。复用部署配置和缓存，不重新下载模型或切换 CPU。
- 格式：PDF（含扫描件）、DOCX、XLSX、UTF-8 TXT。旧 DOC/XLS、PPTX、独立图片等不在正式支持范围。
- Embedding：用户指定网关 `https://tokendance.space/gateway/v1`，模型 `qwen3.7-text-embedding`。
- 生成：DeepSeek 在线 API，当前配置模型 `deepseek-flash`。不要无故改用户模型/网关/thinking 配置。
- RAG：单文档、单轮、非流式；没有聊天历史持久化；摘要与数据提取仍未接入。
- 每次问题最多一次查询 embedding 与一次生成；无自动模型重试、无自动重建索引。
- 模型内部输出 JSON，后端分配引用编号并校验；前端显示 Markdown、逐事实引用、解析版本和来源入口。
- 状态：`answered`、`clarification_needed`、`insufficient_evidence`。合法无依据返回 200；不合规模型输出受控返回 502。
- A 版本/索引有效时，B 解析失败、B 尚未索引或索引构建失败，不破坏 A；生成期间固定快照。

## 5. 当前必须解决的 S05

当前 Prompt：`rag-qa-v3`。

问题：**“样本公司的采购审批流程包含哪几个环节，超过多少金额需要总经理批准？”**

本次入选资料：

- [1] `第二十条 采购金额超过十万元的，应当报总经理批准。`
- [2] `采购需求的提出、比价与合同签署环节由采购管理制度分别规定。`

v3 实际输出中，结论正确写“采购金额超过十万元的，应当报总经理批准。[1]”，但补充说明写：

> 因此本次可确认的审批金额门槛为十万元；至于流程环节的完整名单，本资料只作了指向性说明，未列出具体环节。[2]

补充说明中的“十万元”不能由 [2] 支撑。即使前文引用了 [1]，此句仍是错引。模型 JSON 合法、引述真实不等于语义正确；本例通过机械校验，但必须在语义验收计失败。

已有回归：

`test_repeated_amount_in_explanation_still_needs_its_own_correct_reference`

注意：该测试证明**评估器能抓住反例**，不证明真实模型已经修复。需要后续真实复测。

可研究的改进方向（尚未实施，需自行评估）：

1. 减少补充说明对结论中数字、期限的无必要重复。
2. 让一个事实条目只表达一个可归属的论断；复合句拆成分别带正确 refs 的条目。
3. 用相同失败机制的多个独立例子检查，不只对“十万元”硬编码。
4. 如需调整输出协议，同步修改 Prompt、Pydantic/校验器、渲染、测试及任务书说明，不悄悄改变契约。
