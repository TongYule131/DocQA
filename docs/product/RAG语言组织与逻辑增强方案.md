# RAG语言组织与逻辑增强方案

日期：2026-10-23。任务编号：RAG-L01。优先级：P0，当前RAG开发最高优先级。

用户反馈：现有回答能召回较多相关内容，但答案像片段拼接，缺少语言重组与连贯论证。下一阶段优先改善生成与表达，既有检索、数字角色、引用与数学证据能力继续保留；S2候选融合／精排等剩余事项后移。用户反馈不能直接等同于经过独立测量的总体高召回率，本任务评估须固定实际装入证据。

本文包含原方案与实际隔离实施／验收。正式仍为rag-task-v33／fact-context-parts-v7；候选v34完成12题A/B，随后v35接入分题型组织并复测4题，尚未通过上线出口，未修改正式提示词、协议、数据库或模型配置。本轮使用追加40次及原有4次余额，累计168／168。整体阶段状态见[ragent对比方案](ragent代码对比与提升方案.md)，发布状态见[接力说明](../稳定试用版接力说明.md)。

## 1. 代码核对后的问题定位

| 已核对的实现 | 对表达的影响及判断边界 |
| --- | --- |
| [当前提示词](../../app/rag_prompts.py)已经允许忠实转述，并区分直述／综合／推断 | 不能把问题简单归为“系统禁止改写”。但提示词主要篇幅要求逐事实完整限定、拆分指标与覆盖子问，缺少统一的回答组织策略；这可能使模型倾向逐项复述，仍需固定证据对照验证 |
| [知识库worker](../../app/knowledge_worker.py)把conclusion和explanation逐项拼成段落 | 当前没有独立的正文结构；事实输出顺序直接成为阅读顺序。仅增加“自然流畅”提示，很难完全解决整篇组织问题 |
| [限定展示](../../app/rag_answer_contract.py)及worker会在正文后追加尚未逐字出现的context | 条件完整得到保护，但容易形成重复括注；忠实改写了限定也可能因字面不同而继续追加，需由实际样本确认，不能直接删除限定 |
| [支持检查](../../app/rag_support_review.py)校验输入范围、完整原句及推断标签等 | 原文引用的精确匹配与正文忠实转述职责不同。应保留精确引用，支持正文重组；现有规则通过不等于完整语义蕴含认证 |
| [渲染与逐事实流式](../../app/web/answer-view.js)围绕事实结构展示 | 新正文编排需要同时覆盖最终回答、流式、刷新恢复和导出，不能只改最后的页面字符串 |

核心改进是让模型围绕用户问题组织论证，再由可核验事实支撑每句话。正文允许改变语序、句式和组织方式；引用原文、数字、对象、条件、否定方向及来源身份保留。

## 2. 目标回答形态

先给直接结论，再解释判断如何成立；按因果、比较维度、概念层级或流程组织，结尾仅在用户需要时回扣边界。短事实题可以一两句话回答，综合题通常用数个连贯段落；不为所有问题统一套“结论／依据／总结”模板。

以跨案例问题为例，目标结构是：

1. 直接指出决定差异的关键条件，而不是先把案例甲、乙各摘一段。
2. 在同一比较维度解释两者如何不同，各项判断绑定各自证据。
3. 将接受机制、研发运营和平台条件组织成递进解释，不能只列三个名字。
4. 回扣传统文化保留与跨文化接受的关系，并给出证据允许的适用边界。

这是回答结构示意，不是本次对原论文的新生成或语义验收结果。

## 3. 第一阶段：提示词改造，保持现有协议

交付RAG-L01-A：在当前规则中增加紧凑的“作答组织”章节，并整合重复要求。不是不断叠加历史失败题专用模板；保留来源边界、数字限定、公式冲突、推断标注及子问覆盖约束。候选版本建议rag-task-v34，正式版本仅在实际实施和验证时递增。

建议提示词草案：

```text
# 作答组织与语言表达
你的任务是用资料支持一个直接、连贯的回答。先确定用户需要的核心判断，
再按该判断所需的解释顺序组织正文，不按检索编号、页码或片段出现顺序逐段复述。

1. 开头直接回答核心问题。后续事实围绕这一判断展开，不重复开头的结论。
2. 正文使用你自己的语言忠实转述。可以改变语序、合并重复表达、解释明确的
   概念联系；保留专名、数字、单位、主体、条件、例外、否定方向和原有不确定性。
   引用证据单元仍须为所提供的真实原文，不将转述写成原文引号。
3. 综合题按“问题—机制—结果—边界”组织；只有证据支持因果关系时才写因果。
   比较题按共同维度比较，而不是写两份独立摘要。概念题说明划分依据与关系。
   短事实题直接回答，不强制补背景或长篇论证。
4. 每条text写成完整、自然的回答句。使相邻条目在含义上衔接，避免反复以
   “文档指出”“论文提到”“根据材料”起句；不依靠上一条的引用替本条补证。
5. “因此、导致、说明、相反、只有、必然”等会改变论证强度。
   使用前核对证据是否支持该联系：共同出现不等于因果，局部结果不等于普遍结论，
   挑战存在不自动支持某种解决主张。来源未明确的结构判断标inference并保留边界。
6. 将必要条件尽量自然写入text，同时按现有context协议记录真实原文限定。
   不通过省略统计口径、对象、期间或例外来使回答更简洁。
7. 结论、解释和结尾各自提供新信息。每个子问都要实际回应，不能用通用背景、
   泛化总结或流畅但无证据的衔接句替代缺失依据。
8. 对同一事项的公式与正文冲突，同时陈述两端，不擅自选择一端或替作者纠错。
   证据不足时具体指出缺口；不得通过组织措辞把不确定结论变成确定结论。

在一次回答中完成上述组织与校对，只返回约定JSON；不输出思考过程或自评。
```

这段草案要与原有规则合并，不能覆盖现有JSON字段、每条事实证据选择、数值context和总长度限制。第一阶段仍是一轮生成，不默认增加改稿或评审模型调用。允许模型直接把text写好，但当前“事实即段落”的限制仍然存在；不能承诺只换提示词就完成全部组织改造。

## 4. 第二阶段：事实记录与正文编排分离

交付RAG-L01-B：保留conclusion／explanation里的逐条事实、context、claim_type、evidence、part_ids；增加只负责分组和排序的presentation结构。事实记录供核验，正文按问题逻辑组织，最终句子仍来自已校验的事实文本。

建议的扩展草图：

```json
{
  "presentation": {
    "blocks": [
      {"role": "conclusion", "kind": "paragraph", "fact_indices": [0]},
      {"role": "mechanism", "kind": "paragraph", "fact_indices": [1, 2]},
      {"role": "boundary", "kind": "paragraph", "fact_indices": [3]}
    ]
  }
}
```

这是附加在既有输出字段之外的设计草图，不是当前合法v7响应。fact_indices对应本答案conclusion与explanation的固定拼接顺序，只表达展示关系。role／kind使用有限枚举，不接受未绑定事实的自由标题、引言、总结或连接词字段。

具体原则：

- 同一次模型生成完成整体组织、自然事实句及分组；不将经过校验的答案再交给第二个模型自由改写。
- 每个正文句仍绑定自身事实与证据，引用放在相应句子或分句之后；多句合成一个段落，不把全部引用堆在段尾。
- “两者不同，因此……”中新增的关系也是需要支持的论断，须进入事实记录并引用关系两端及依据。仅列出两端claim_id不能证明因果。
- 编排层不得新增数字、实体、比较结论或否定方向。不能用一个泛化的“综合说明”挂到多个事实后充当新依据。
- 同一事实避免在多个段落重复出现；所有应展示的有效事实都有去向，缺项／澄清单独表达，不因重排丢掉限定或子问。
- 第一版保留必要限定展示。后续可将确实相同、适用于整组且来源明确的条件归并为可见的共用说明，但事实记录仍保留每项限定；不得仅以词面相同推断适用范围。
- 旧答案缺少presentation时沿用旧渲染，保留原文及稳定引用ID，不批量润色历史记录。

用户可见效果是数个完整段落或按比较维度组织的列表；逐事实证据、context及校验详情仍可展开。语言改写在有证据的生成阶段完成，后端不通过正则添加“因此”“这说明”等新论证。

## 5. 第三阶段：关系、覆盖和表达的联合检查

交付RAG-L01-C：将问题级论证需求与现有证据槽位关联，但不把检索任务计划当成来源事实。按题型检查用户实际要求：

| 题型 | 正文应完成的工作 | 重点负例 |
| --- | --- | --- |
| 多跳解释 | 结论、支持机制、必要条件和边界连起来 | 列出三段资料，却没有解释它们如何支持结论 |
| 案例比较 | 使用相同维度比较并解释差异 | 案例各写一份摘要，随后凭空补原因 |
| 否定／边界 | 分别判断题干命题及其推导关系 | 有局限写成失效，能缓解写成不需要治理 |
| 概念结构 | 先辨别划分依据，再说明交叉、层级或支持关系 | 因数量相同强配，靠流畅措辞掩盖无依据映射 |
| 数据论证 | 数字服务于解释，保留对象、口径、期间及证据类型 | 把调查／自评数据写成已证明的普遍因果效果 |
| 公式冲突 | 同时引用公式与解释，指出同事项的不一致 | 为追求连贯，删除冲突一端或擅自修正不等号 |

检查分层：结构索引、事实引用、精确原文、数字与覆盖可以执行确定规则；相关／因果、推断强度与完整语义需独立复核。连接词命中或“有因果段落”只是线索，不能作为逻辑已证明的自动通过条件。

缺少关系依据时保留能支持的事实和明确边界。不能通过自动补写一段更流畅的解释来填洞，也不因表达重组反过来扩大检索授权范围。

## 6. 协议、流式及数据库兼容

第一阶段只改任务提示词及其版本／冻结配置，现有输出协议、稳定引用ID和schema14不变。先在隔离环境实施；正式进程不在写草案时重启。

第二阶段需显式升级答案协议和流式能力版本，并同步：生产校验、结构化结果、API／导出、网页渲染、局部事件、刷新恢复及旧结果适配。不能向v7严格字段集合直接偷偷添加presentation。优先使用既有结果JSON和任务检查点，不为排版单独建表；只有确有结构存储需求时才设计数据库迁移。

流式优先发送已经可独立核验的完整句／事实，随后按已声明编排组成段落。局部通过不替代最终覆盖复核；未验证的新衔接句不流出为最终答案。组织层失败时，只能对已完整通过事实与覆盖检查的内容使用确定性的保守排版，并记录表达降级；事实校验失败仍不发布。不得自动重发不确定的生成请求。

## 7. 固定证据对照与建议验收标准

### 7.1 如何隔离提升来源

固定同一问题、已授权文档、解析版本、实际装入原文、引用单元、模型／网关／thinking、上下文上限；只比较提示词或正文组织的一项变化。保存新旧原始输出、最终展示、配置及证据哈希。先用已有响应和合成输出验证兼容／渲染，不为检查页面重新调用模型。

从已有评估规划中选择首批12题：短事实2、多跳3、案例比较2、概念2、否定边界2、公式冲突1。题目分组、最小依据、禁用结论与评分标准在新生成前冻结；同文档不得跨开发与独立保留组。旧论文反复修复题只能作开发回归；缺少独立保留样本时明确待构建。此子集不冒充原方案建议60题已完成。

### 7.2 分开评价表达和忠实性

以下是建议出口，实施前冻结，不是当前实测成绩：

- 盲评组织性、连贯性、直接回应、简洁性各1～5分，四项平均至少4分；短事实题不得因冗长解释降质。
- 新旧成对比较至少9／12题倾向新版；存在正确性或关键条件退化的题目不能用其他题的文笔分抵消。
- 接受集的引用／原文范围规则全部通过；关键实体、数字、单位、否定、条件和公式冲突无已发现的新增错误。语义边界仍以实际人工复核为准。
- 多跳题的必需论证环节在正文实际出现，并有正确来源；“最终可见信息完整”和“内部事实表完整”分别检查。
- 保留重复句、重复起句、原文重合片段等诊断指标，供定位拼接问题；不能将“复制比例低”直接当作高质量，更不能为降低重合度改写专名或数字。
- 记录首个有效句延迟、总耗时、输出长度和真实usage，报告相对基线变化；首版默认每题仍一次生成，性能出口按冻结基线和样本分布确定，不虚构P95提升。

优先采用人工成对盲评，尽可能由不同于实施者的人复核；没有独立复核就标开发复核。若后续启用模型judge，其模型、提示词、费用和失败样本另记，不把同一模型的自评当成最终质量证明。

### 7.3 费用和回归约束

方案和文档检查均为0供应商调用。制定方案时唯一累计账本124／128，余4；此后用户追加40次，将同一账本上限扩至168。本轮已用追加40及原有4，累计168／168；不得另建账本或自动扩限。在线阶段先冻结具体题目、旧响应是否可复用和逐HTTP上限；不足部分保留待验，不重跑所有已通过历史题。新增预算按用户授权记录执行。

本地只直接运行本次改动对应的提示词／事实协议／渲染／流式／恢复定向检查；本地全量仍须用户对本次运行明确同意。GitHub CI按既有分级策略执行，离线通过不等于表达或逻辑语义已通过。

## 9. 实际隔离实施与验收（2026-10-23）

**结论：工程候选已实现，整体语言／逻辑验收未通过，不切换正式服务。** 原12题中候选较好6题、持平3题、旧版较好3题，未达到预先冻结的至少9／12题偏好候选出口。相同模型匿名成对复核只作开发辅助，不是独立人类盲测；开发复核另发现把原文“可以助力”强化为“才能”的必要条件越界，该问题不能用文笔分抵消。

### 9.1 已实现与当前边界

- 隔离v34／fact-context-parts-v8：同一次生成分别输出有证据的事实与presentation编排；正文只能组合已校验事实，编排不能夹带自由衔接句、重复或遗漏事实。仍保留原文、数字、条件、稳定引用及v7旧结果兼容。
- 同步了文档问答、知识库worker、结果持久化、Markdown导出和validated-fact-stream-v2局部段落编排。局部核验不代替最终整体发布；本轮新v2只做离线流式／DOM检查，未执行新供应商SSE或正式页面验收。
- 用户随后要求直接按题目区分作答。隔离v35新增task-aware-composition-v1，单文档兼容入口与知识库入口都在实际模型提示词中选用有限策略；策略及哈希进入配置冻结，不新增分类模型HTTP或数据库表。

| 题型 | 实际组织规则 |
| --- | --- |
| 事实 | 一两句直答，限所问对象与必要条件 |
| 文档概述 | 研究问题、核心论证、结论与限制 |
| 多跳 | 中心判断、机制联系及边界 |
| 比较 | 用共同维度比较对象，再解释差异意义 |
| 概念 | 区分类分依据、层级与关系，避免重复定义 |
| 否定／边界 | 分别判断子命题与推导是否成立 |
| 公式核对 | 公式与正文分端引用，冲突不能擅自消解 |

表达分类独立于检索预算分类：额外问号或“一句话回答”不直接算多跳，“人工智能模型”不直接算公式核对；复合题选择一种主组织并补必要边界义务，不堆七套模板。这是可审查的本地规则分流，未独立测量泛化识别准确率。

### 9.2 固定证据A/B成绩

## 10. 第二轮实施方案：按题型先选材和组织，再写正文（新增40次已授权）

本节保留执行前的方案与预算分配；实际实施、失败和剩余工作见第11节。

用户2026-10-23询问下一步优化并允许追加40次。已在原累计账本168／208登记授权，余40；原168条调用、首次失败及评估版本保留。本次只核对原因、更新实施方案与授权，没有新供应商HTTP，没有修改正式代码或数据库。以下是下一轮设计，不是已实现或已测成绩。

### 10.1 本轮要改变的机制

v35已经会选择不同题型策略，但模型仍面对长原文单元，一次承担选材、判断关系、写句子和满足严格协议；展示层只能合并已生成事实，不能替它剔除无关内容。每条context与正文不逐字相同时还会追加原文，因此忠实转述也可能形成重复括注。下一轮从事实选择和段落职责入手，合并重复提示规则，继续保留引用、数字和限定保护。

| 顺序 | 改动 | 约束与可验收结果 |
| --- | --- | --- |
| 1 | 区分候选证据与最终作答事实 | 检索到的内容不必全部写入回答。短事实只选所问对象的最少充分条款；同段其他对象规则不能因为引用在同一单元就一并输出。适用例外、共享限定或否定不能为简洁被删 |
| 2 | 细化可选择的原文单元 | 只在已授权、实际装入范围内按句／条款产生不可变原文位置，保留必要限定与跨页续句绑定；不修改原解析／索引，不用模型摘要代替原文。范围不清时不凭字符串相似度删掉条件 |
| 3 | 复杂题先输出简短结构计划 | 计划只声明要回答的槽位、比较维度、段落职责和已存在证据ID，不是推理过程或新证据。校验ID、引用范围、覆盖、配对两端及冲突两端后，再把所选真实原文交给写作；不把计划中的概括当作事实来源 |
| 4 | 按题型写作 | 事实、概述、比较、多跳、概念、边界、公式使用各自组织约束；相邻段必须增加信息，不能换一句话重复中心结论 |
| 5 | 统一展示与语义复核 | 保留逐句引用、完整条件和推断性质；有利因素不能加强为必要条件，自愿反馈不能写成因果效果，冲突不能擅自消解。形式检查与语义判断分别报告 |

这里是“固定原始候选证据”的对照。经规划后送给写作的证据会有意缩小，须分别保存原始输入、选择计划、写作输入及其哈希；不能把效果说成完全相同模型输入下的纯提示词收益。计划只能收紧原已授权范围，不能扩库、换解析版本或新增来源。

### 10.2 不同题型的正文责任

| 题型 | 写作前必须明确 | 正文出口 | 主要防错 |
| --- | --- | --- | --- |
| 事实 | 所问对象、规则、决定判断的限定／例外 | 通常一两句；不问其他对象就不扩写其规则 | 例外必须先判断适用，不能全删或全抄 |
| 比较 | 共同维度、每个维度两侧证据 | 同一维度内比较两对象，再解释差异意义 | 不按甲摘要、乙摘要拼两篇；一侧缺依据就明确缺项 |
| 多跳 | 中心问题、必要环节、各环节的联系依据 | 判断—机制—结果／边界，各段说明支持关系 | “共现”不改写成因果，助益不改写成必要／充分条件 |
| 概念 | 两组概念的划分依据、层级及联系 | 定义为关系辨析服务，仅在必要位置解释一次 | 不因数量相同强配，不在开头和后文重复整组定义 |
| 否定／边界 | 各子命题及题干推导关系 | 逐项判断并交代限制 | 不能只列背景或只否定其中一项 |
| 公式核对 | 同事项公式、条件与相邻解释 | 两端并列，指出方向／范围是否一致 | 不修原文、不删除冲突端，不判定未证实的笔误端 |
| 文档概述 | 研究问题、主要论证、作者结论与范围 | 展示全文组织或明确当前仅覆盖部分 | 不把少数相关段落当全文读完，不堆所有例子 |

复杂题首轮拟仅对比较、多跳、概念增加独立规划步骤；事实、边界、公式先沿用一次生成，避免对已经足够清楚的题目统一增加成本。若短事实选材不能在离线及校准中稳定守住所问对象，就停止该设计，不把单次生成或低调用数当成必须坚持的目标。

### 10.3 提示词、展示与运行约束

1. 将通用来源／协议规则与本题组织任务分开，合并相同限制和历史样例；模型只接收本题必要的组织指令。整理前后逐条对应已有保护，不能为缩短提示词弱化来源、数值或覆盖校验。
2. 原文quote及坐标永远保留。展示去重只允许可证明等价的版式差异；不能用语义相似度就认定限定已在正文完整表达。未被正文完整保留的必要限定不能只藏入审计详情。
3. 增加论断强度与无关事实的负例复核；系统可以标记或拒绝缺少依据的关系，不能把“才能”静默替换成“可以”来伪装原始生成合格。模型自评不充当最终放行依据。
4. 每个真实HTTP调用前预扣同一账本，失败／不确定均计入，不自动重试。复杂题若需要规划＋写作，必须在任务中明示调用预算与阶段、固定规划检查点，恢复只复用有效计划；不能让界面仍标一次生成、后台却悄悄发送两次。
5. 当前question_calls允许embedding／generation，question_checkpoints只允许retrieval／answer／evidence。新增规划的检查点结构需先在隔离环境设计验证；不得直接写不存在的role，也不因增加步骤擅自迁移正式库。
6. 模型、网关、thinking、原解析及索引保持，降低对照干扰。当前正式仍v33／v7／schema14；v35候选与下一轮实现分目录保留，不在运行根目录试改代码。
