## 当前产品定位与入口

DocQA是本地团队试用的文档助手。管理员准备资料和授权，客户在允许的资料范围内问答、追问、查看原文并反馈；摘要和提取保留为文档工具。公网SaaS、多租户、商业计费、企业单点登录、跨会话长期记忆和自主多动作Agent均不因现有代码而获得验收。

| 入口 | 已有职责 | 尚需补齐的产品出口 |
| --- | --- | --- |
| `/app` | 统一会话、库内资料筛选、多行输入、临时资料、引用和历史 | 连续真实业务及窄屏／空态／失败操作的人工试点 |
| `/admin`、`/knowledge` | 资料准备、发布／生效、授权、用户和任务管理；N04已补齐并正式更新账号安全流程 | 真实管理员业务手册／人工业务验证 |
| `/admin/intents`、`/admin/traces` | 意图配置／测试台、实际执行追踪 | 覆盖动作、资源、对象、参数和缺数据的整问评估 |
| `/tools`、`/admin/documents` | 文档工程、摘要和提取 | 沿用固定解析版本、完整覆盖与历史导出要求 |

客户端不展示PID、schema、密钥或原始JSON。证据不足、资料处理中、未授权、配额不足和失败分别给可操作提示；管理员诊断不自动取得客户正文。已有蓝白布局不是全产品人工验收证据。

### P1自动分流交互（开发候选）

用户于2026-10-29确定普通问题直接LLM、文档请求才读知识库。拟采用默认自动判断，允许无资料聊天，已选资料仅限定可读集合；闲谈不触发实际数据查询。受控Agent、上下文额度及压缩的完整计划归[阶段07](阶段07-后续任务与验收.md)，当前本页能力表仍描述已部署实现。文档质量助手、业务MCP、反馈复现等Agent场景按该计划分批且保持动作／权限／费用边界，用户随后授权先实施任务1，当前候选已接通普通LLM、可选知识库、显式资料范围、普通流式／历史／导出及通用标签，未正式迁移／部署。已选资料正在准备时，普通问题不等待；实际文档任务才释放worker执行位并持久等待，完成后复用原分流检查点，不重复调用。无资料的文档题提示选材料，普通问题保持可发送；旧资料准入、来源与引用校验不移除。用户随后已授权P2，当前候选增加本人用量／预留／计量余量、未验证窗口提示和后台汇总；用量读取不阻塞对话，执行额度由服务端强制，详见阶段02／05。P2本批不包含Agent或模型摘要；用户另于2026-10-30授权P3，候选边界见下节，模型摘要仍待P4。

### P3查阅记录（开发候选，默认关闭）

2026-10-30用户授权任务3。统一知识问答增加有界决策与最多一次补查，契约归阶段02；这不表示已部署、已证明检索收益或开放任意工具。客户实际执行时看到“核对证据缺口／按缺口补查原文”等阶段，回答下默认收起的“资料查阅记录”只显示实际动作及停止说明，不展示模型思考或模拟“已读全文”。普通回答不进入文档Agent。

管理员链路详情新增有界检索记录：独立状态、每轮原文可见范围、请求变化，以及原时序中的实际决策／补查／写作耗时；逐请求usage与发送状态另行展示，未知不写零。公开投影不含问题、文档正文、短检索理由或原始响应。补查无新增、上下文不足、相同查询、全部缺证据和必要澄清分别记录；未补齐的条件不能由最终正文抹去。工程、首次失败及隔离页面范围见阶段05，真实业务收益仍待阶段04的独立验证。

系统设置的配置展示不等于网页内可修改服务器模型或密钥。新库的模型和分块参数在创建时固定；分块修订生成新草稿，重新索引并生效后才供客户使用。新账号由管理员选择角色和初始密码；固定123456及强制改密对应明确的重置操作。停用撤销登录并停止后续处理，最后一个有效管理员不能被停用。

管理员主导航为知识库、意图管理、反馈处理、链路追踪、用户管理和系统设置；反馈页沿用相同侧栏及当前页状态。文档工具仍从原工作区入口进入。手机和桌面分别保存侧栏收起偏好，避免桌面展开状态遮住手机内容。执行时序将节点、类型、状态、时间线和耗时分列；成功、失败及运行中统计分别显示。

## 资料准备与会话闭环

```mermaid
flowchart LR
    A[选择团队库或私有临时库] --> B[上传与登记]
    B --> C[解析和结构分块]
    C --> D[索引]
    D --> E{自动生效或逐份审核}
    E --> F[授权会话与资料筛选]
    F --> G[检索和校验后流式回答]
    G --> H[原文复核与用户反馈]
    H --> I[授权分享的复现和回归审核]
```

统一入库已协调解析、索引和按策略生效；工程上传只保存原件。**上传完成、解析完成、索引可用、已生效且获授权是不同状态**。默认逐份自动生效，也可逐份审核；不能把旧“所有文件均须手工发布”的首版方案继续当成唯一流程。新版本失败保留旧可用快照，显式替换成功后才切换。

新会话固定知识库，单文档是库内筛选，切库新建会话。无资料的空选择应禁用发送，不偷偷回退全库；处理中问题持久等待，就绪后只提交一次。旧文档会话、任务和结果经适配读取，保留原身份、来源和请求历史。

资料选择提供“全选可用”“全不选”、名称搜索和逐份“仅此份”；新会话首次默认空选择，已存在会话保持其历史范围。同一浏览器会话中按账号、知识库及会话保存明确选择，刷新不把全不选变成全库；跨浏览器或关闭浏览器后的长期偏好未实现。上传成功会显式选中本次上传资料。

临时资料只属于当前用户／会话或私有临时库，不静默转入团队库。到期、撤回、删除先阻止读取与后续执行，再按阶段03明确停机维护清理；不按旧设计建议“7天”覆盖实际配置。正文、草稿、分享、澄清和记忆的生命周期一起验收，费用墓碑和来源历史不得据此重置。

## 权限、输入与阅读体验

权限覆盖资料、候选、执行、结果、原件、导出和SSE每次读取，服务端默认拒绝；隐藏按钮不能代替授权。授权范围为账号、知识库、用户选择和快照的交集；撤权后缓存、排队计划和已连接事件流也必须重新核对。

Enter发送、Shift+Enter换行，输入法组合期间不误发；上传状态与是否可发送一致。用户翻历史不强制跳底，保留回到最新；引用抽屉显示实际来源与版本，不伪造PDF页码或字符高亮。停止输出不承诺上游立即停止计费。模型、文件名、链接和引述按不可信文本安全渲染。

公共图标固定尺寸并居中；控件按所在区域统一高度，窄屏标题和操作区允许整项换行，表格操作列可固定在可视边缘。个人设置、账号安全、返回工作台均有边框与点击区域；退出登录使用深红文字和浅红背景。菜单互斥、外部点击及Escape可收起，避免多层面板重叠。个人资料与重置说明统一行距／间隔，空状态不留无意义大空隙；具体实测范围见阶段05，不能据此宣称所有尺寸和页面完美。

结构化对象、条件及来源轮次服务于理解，旧答案不是新证据；更正、关闭／清除、撤权和到期使旧计划失效。刷新和断线恢复同一任务，不新建请求。真实流式的局部块仍是生成中，最终协议／覆盖／引用通过后才是正式结果，见[阶段02](阶段02-检索与问答.md)。

## 账号与双端流程（B01～B04）

已有登录、管理员／客户、知识库授权、会话归属、头像与后台分区。2026-10-28的N04开发候选补齐以下流程，并用隔离合成账号核对；2026-10-29获用户授权后随N01～N04整包正式更新，工程检查、GitHub CI和正式运行时点只在阶段05维护：

1. B01：客户和管理员从“个人设置”保存显示名称，刷新后保持。服务端只修改当前账号，拒绝传入其他user_id或username；登录账号及历史归属保持。头像仍按原私有存储规则处理。
2. B02：从“账号安全”输入原密码、新密码及确认密码。服务端核对原密码、两遍一致且不同于旧密，沿用4～32位；兼容原有最长128字符旧密码的验证。成功在同一事务内修改哈希、撤销全部登录并写审计，页面清空口令后重新登录。旧密错误、重复新密、长度或确认错误不改密码；验证失败有持久限流，并发改密只允许一个提交。已连接事件流也核对原登录是否仍有效。
3. B03：管理员确认后只重置固定初始密码`123456`。重置接口不接受客户端密码字段，界面也不提供任意新密输入；同时撤销登录、设置持久的强制改密状态并写审计。下次登录只能访问改密／退出等必要入口，直接旧API、管理角色和刷新均不能绕过；改密成功后重新登录恢复业务。重新启用账号不会清除原强制状态。管理员可在用户管理查看最近30条安全操作或用受限接口按账号查询，记录不包含密码、哈希、cookie或CSRF值。
4. B04：用户端菜单和管理端侧栏均有个人设置及安全入口。390像素下设置弹窗和强制改密表单可用；手机侧栏默认收起并在选择历史后收起。真实Chrome核对管理员重置→客户首次改密→新密码登录→旧回答保持及同会话继续问答；供应商为桩，越权及旧登录拒绝另有API检查。这是隔离工程验收，不替代真实业务人工试点或N06跨登录长期验证。

schema17只新增账号状态及安全事件表，迁移保留既有用户／哈希／会话／头像／资料／来源和结果，不为历史账号自动设置强制改密。隔离v16→v17、故障回滚、备份与另一目录恢复已核对。实现、接口／浏览器证据和正式发布状态见[阶段05](阶段05-代码审查与加固.md)及[阶段07](阶段07-后续任务与验收.md)；测试未修改真实账号，也未主动注销用户。

## 真实业务MCP与条件扩展（B05～B06）

B05先明确一个业务问题、真实接口、授权主体、字段含义、样本、数据新鲜度和调用成本，再实现只读适配与缺参续问。已有Schema校验、工具登记和模拟HTTP不等于真实企业接入。未配置或未授权必须解释缺数据，不能编造实时结果；混合知识与实时请求先确认范围。

### B05单场景接入契约

首个场景须由真实业务资料确定，不预先复制库存、订单等演示节点。上游已有MCP时核对协议和工具契约；只有普通HTTP接口时，再按该接口实现薄的只读MCP适配层，沿用DocQA现有工具登记和执行链。暂不引入多工具自主编排、写入动作或新的集成平台。

| 契约项 | 接入前必须明确 |
| --- | --- |
| 业务与主体 | 用户实际要问的问题、允许查询的账号／组织、资料所有者和授权依据 |
| 接口与凭据 | 接口文档、本机／服务地址、协议版本及真实工具名；密钥只配置服务器环境变量，文档只写引用名 |
| 参数与范围 | 必填／可选项、类型／枚举／默认值、实体标识、时间范围、分页与最大返回量；缺参先确认，不由模型猜造 |
| 返回含义 | 字段、单位／币种／时区、空值与无记录、业务错误、数据截至时间及过期规则；查询时间不等于数据更新时间 |
| 权限执行 | DocQA用户／库授权与上游业务数据范围的可信映射；服务端执行组织／行范围约束，不能信任模型提取的租户参数 |
| 样本与费用 | 脱敏请求／响应及必要负例；模型HTTP、业务HTTP、入口HTTP、失败／不确定及可能费用分别登记 |

管理员的`read_only`登记是本地限制，不能证明上游接口无写入副作用或已实施行级权限。现有代码按工具／知识库授权，并未自动把DocQA当前用户或组织转换为企业接口的行权限；完成真实适配前不得用共享服务凭据宣称每个客户都具备相同业务查询权。

完整参数的现有**工具执行子路径**为一次模型参数提取，再发送`initialize`、`notifications/initialized`、`tools/call`三次业务HTTP；缺参轮只提参而不发业务HTTP，补参续问会再次提参。这个数不包含入口HTTP或可选意图／其他模块调用，也不是整个试点的新预算。真实执行前须按实际输入冻结全路径，复用阶段04的唯一真实调用账本，逐任务账本不替代阶段总账；现有N01～N03批准适配的scope不能直接改成N05或借用已关闭余量。

工具成功展示实际返回内容及工具来源，继续区分文档引用；当前`tool_source.queried_at`只说明查询时间。返回字段语义、截至时间和业务范围需要真实契约及相应校验，不能由界面上的时间戳代替。技术负例由隔离传输验证；真实字段正确、数据完整及业务可用须结合上游样本和人工核对。新的逐题业务标注先交用户审核封存，再执行或评分，阶段出口只见阶段07。

B06涉及新解析档位、数学表示、新资料重解析／索引及规模扩展时，先核对阶段01的质量门槛和阶段03的容量实测。没有必要样本／收益证据不更换GPU、模型或存储，不把现有公式可见性当作全公式理解。
