# 阶段06：产品工作台、账号与业务接入

本页整合原product计划的有效产品职责和验收要求。已有实现与待办分开；当前代码／发布见[阶段05](阶段05-代码审查与加固.md)，逐项状态见[阶段07](阶段07-后续任务与验收.md)，原设计和原型只在[历史归档](archive/2026-10-26-consolidation/followup-2026-10-27/index.md)。

## 当前产品定位与入口

DocQA是本地团队试用的文档助手。管理员准备资料和授权，客户在允许的资料范围内问答、追问、查看原文并反馈；摘要和提取保留为文档工具。公网SaaS、多租户、商业计费、企业单点登录、跨会话长期记忆和自主多动作Agent均不因现有代码而获得验收。

| 入口 | 已有职责 | 尚需补齐的产品出口 |
| --- | --- | --- |
| `/app` | 统一会话、库内资料筛选、多行输入、临时资料、引用和历史 | 连续真实业务及窄屏／空态／失败操作的人工试点 |
| `/admin`、`/knowledge` | 资料准备、发布／生效、授权、用户和任务管理；N04候选补齐账号安全流程 | 正式更新及真实管理员业务手册／人工业务验证 |
| `/admin/intents`、`/admin/traces` | 意图配置／测试台、实际执行追踪 | 覆盖动作、资源、对象、参数和缺数据的整问评估 |
| `/tools`、`/admin/documents` | 文档工程、摘要和提取 | 沿用固定解析版本、完整覆盖与历史导出要求 |

客户端不展示PID、schema、密钥或原始JSON。证据不足、资料处理中、未授权、配额不足和失败分别给可操作提示；管理员诊断不自动取得客户正文。已有蓝白布局不是全产品人工验收证据。

## 资料准备与会话闭环

```mermaid
flowchart LR
    A[选择团队库或私有临时库] --> B[上传与登记]
    B --> C[解析和结构分块]
    C --> D[索引]
    D --> E{自动生效或逐份审核}
    E --> F[授权会话与资料筛选]
    F --> G[检索和校验后流式回答]
    G --> H[原文复核与用户反馈]
    H --> I[授权分享的复现和回归审核]
```

统一入库已协调解析、索引和按策略生效；工程上传只保存原件。**上传完成、解析完成、索引可用、已生效且获授权是不同状态**。默认逐份自动生效，也可逐份审核；不能把旧“所有文件均须手工发布”的首版方案继续当成唯一流程。新版本失败保留旧可用快照，显式替换成功后才切换。

新会话固定知识库，单文档是库内筛选，切库新建会话。无资料的空选择应禁用发送，不偷偷回退全库；处理中问题持久等待，就绪后只提交一次。旧文档会话、任务和结果经适配读取，保留原身份、来源和请求历史。

临时资料只属于当前用户／会话或私有临时库，不静默转入团队库。到期、撤回、删除先阻止读取与后续执行，再按阶段03明确停机维护清理；不按旧设计建议“7天”覆盖实际配置。正文、草稿、分享、澄清和记忆的生命周期一起验收，费用墓碑和来源历史不得据此重置。

## 权限、输入与阅读体验

权限覆盖资料、候选、执行、结果、原件、导出和SSE每次读取，服务端默认拒绝；隐藏按钮不能代替授权。授权范围为账号、知识库、用户选择和快照的交集；撤权后缓存、排队计划和已连接事件流也必须重新核对。

Enter发送、Shift+Enter换行，输入法组合期间不误发；上传状态与是否可发送一致。用户翻历史不强制跳底，保留回到最新；引用抽屉显示实际来源与版本，不伪造PDF页码或字符高亮。停止输出不承诺上游立即停止计费。模型、文件名、链接和引述按不可信文本安全渲染。

结构化对象、条件及来源轮次服务于理解，旧答案不是新证据；更正、关闭／清除、撤权和到期使旧计划失效。刷新和断线恢复同一任务，不新建请求。真实流式的局部块仍是生成中，最终协议／覆盖／引用通过后才是正式结果，见[阶段02](阶段02-检索与问答.md)。

## 账号与双端流程（B01～B04）

已有登录、管理员／客户、知识库授权、会话归属、头像与后台分区。2026-10-28的N04开发候选已补齐以下流程，并用隔离合成账号核对；正式版本尚未更新，工程检查与本次单独批准的全量结果只在阶段05维护：

1. B01：客户和管理员从“个人设置”保存显示名称，刷新后保持。服务端只修改当前账号，拒绝传入其他user_id或username；登录账号及历史归属保持。头像仍按原私有存储规则处理。
2. B02：从“账号安全”输入原密码、新密码及确认密码。服务端核对原密码、两遍一致且不同于旧密，沿用4～32位；兼容原有最长128字符旧密码的验证。成功在同一事务内修改哈希、撤销全部登录并写审计，页面清空口令后重新登录。旧密错误、重复新密、长度或确认错误不改密码；验证失败有持久限流，并发改密只允许一个提交。已连接事件流也核对原登录是否仍有效。
3. B03：管理员确认后只重置固定初始密码`123456`。重置接口不接受客户端密码字段，界面也不提供任意新密输入；同时撤销登录、设置持久的强制改密状态并写审计。下次登录只能访问改密／退出等必要入口，直接旧API、管理角色和刷新均不能绕过；改密成功后重新登录恢复业务。重新启用账号不会清除原强制状态。管理员可在用户管理查看最近30条安全操作或用受限接口按账号查询，记录不包含密码、哈希、cookie或CSRF值。
4. B04：用户端菜单和管理端侧栏均有个人设置及安全入口。390像素下设置弹窗和强制改密表单可用；手机侧栏默认收起并在选择历史后收起。真实Chrome核对管理员重置→客户首次改密→新密码登录→旧回答保持及同会话继续问答；供应商为桩，越权及旧登录拒绝另有API检查。这是隔离工程验收，不替代真实业务人工试点或N06跨登录长期验证。

候选schema17只新增账号状态及安全事件表，迁移保留既有用户／哈希／会话／头像／资料／来源和结果，不为历史账号自动设置强制改密。隔离v16→v17、故障回滚、备份与另一目录恢复已核对。实现、接口／浏览器证据和未发布状态见[阶段05](阶段05-代码审查与加固.md)及[阶段07](阶段07-后续任务与验收.md)；测试未修改真实账号，也未主动注销用户。

## 真实业务MCP与条件扩展（B05～B06）

B05先明确一个业务问题、真实接口、授权主体、字段含义、样本、数据新鲜度和调用成本，再实现只读适配与缺参续问。已有Schema校验、工具登记和模拟HTTP不等于真实企业接入。未配置或未授权必须解释缺数据，不能编造实时结果；混合知识与实时请求先确认范围。

B06涉及新解析档位、数学表示、新资料重解析／索引及规模扩展时，先核对阶段01的质量门槛和阶段03的容量实测。没有必要样本／收益证据不更换GPU、模型或存储，不把现有公式可见性当作全公式理解。

本表沿用原产品场景编号，均属于“产品”命名空间；其中C02记忆清除场景与禁止重发的RAG在线题C02不同。表内“必须观察”是标准，实际工程证据与人工试点状态在阶段07的V01／V02，不能整表标全过。

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| U01 | 长问题、粘贴和中文输入法 | 多行可编辑；组合输入的 Enter 不误发；单次发送只创建一轮 |

资料更新失败、跨文档条件冲突、撤权、重复订阅、到期后不可复核及恢复后旧结果都要保留独立负例。5名在线／2并发只是原待测场景，未实测档位不得成为容量承诺。权限越界、错误公开、重复收费、来源丢失、不可恢复和未完成冒充成功仍是阻断项。
