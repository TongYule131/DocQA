# DocQA M5 恢复演练：不调用任何模型，仅使用真实迁移、任务、worker 与结果持久化。

**用途**：在**独立数据目录**中验证 Windows 启停入口、迁移备份、任务中断、结果持久化
与重启后查看／恢复。脚本**不发起任何模型调用**（在线预算只用于语义验收）。

```powershell
cd D:\python\DocQA
# 1) 启动（独立目录 + 独立端口）
powershell -ExecutionPolicy Bypass -File scripts/start_local.ps1 `
  -DataDir data/stable-release-dev/m5-run -Port 8123

# 2) 注入一份合成解析版本（不重跑 OCR、不下载模型）
$env:DOCQA_DATA_DIR = 'D:\python\DocQA\data\stable-release-dev\m5-run'
.\.venv\Scripts\python.exe scripts\seed_recovery_sample.py --data-dir data/stable-release-dev/m5-run

# 3) 通过 API 创建分析任务（只写库，不产生调用）
# 4) 用注入的固定模型完成一次任务并发布结果
.\.venv\Scripts\python.exe scripts\seed_recovery_sample.py --data-dir data/stable-release-dev/m5-run --run-job

# 5) 停止 → 重启 → 只读查看结果与账本
powershell -ExecutionPolicy Bypass -File scripts/stop_local.ps1 -DataDir data/stable-release-dev/m5-run
powershell -ExecutionPolicy Bypass -File scripts/start_local.ps1 `
  -DataDir data/stable-release-dev/m5-run -Port 8123
powershell -ExecutionPolicy Bypass -File scripts/status_local.ps1 -DataDir data/stable-release-dev/m5-run
```

## 观察点

| 观察点 | 期望 |
| --- | --- |
| 迁移 | 空库自动建到 `SCHEMA_VERSION=3`；旧库升级前生成一致性备份 |
| 端口冲突 | 端口被占用时脚本报告占用者并退出，**不终止**该进程 |
| 进程归属 | `data/_local-service-logs/*.json` 记录 PID、启动时间、可执行路径、角色、端口、数据目录 |
| 停止 | 仅停止身份与数据目录都匹配的进程；不匹配则跳过 |
| 任务恢复 | 租约过期且无残留调用 → 回到 queued；有残留调用意图 → needs_attention，**不自动重发** |
| 结果持久化 | 重启后 `/api/analysis-results/{id}` 与导出仍可读，且 `requests_used` 不变 |
| 无隐藏调用 | 启动、刷新、状态、能力、规划、查看与导出都不产生模型调用 |

## 证据位置

- 服务日志：`data/_local-service-logs/<role>.out.log`、`<role>.err.log`
- 进程记录：`data/_local-service-logs/<role>.json`
- 演练输出：`data/stable-release-dev/m5-evidence/`
- 上述目录都在 Git 忽略的 `data/` 下，不入库。
