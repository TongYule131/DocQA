## 初次验收发现及修复

初始项目自带测试为 **102 passed**，但独立构造的 12 个任务书反例均失败。这些失败分别指向以下问题，不能用原测试数量代替业务验收。

| 问题 | 原行为与影响 | 本轮修复 |
| --- | --- | --- |
| P1 新版发布删除旧版和索引 | `_retire_old_versions` 删除旧版本、分块、索引，B 成功后 A 不能检索 | 取消自动删除；预览指针与索引指针独立，历史版本保持可读 |
| P1 候选索引覆盖原索引 | 构建前把原记录改为 indexing，失败后改成 failed | schema v2 支持多条索引；候选独立记录，全量写入与切换在同一事务中完成 |
| P1 部分成功被发布 | partial_success、未知/缺失转换状态均可发布 | 只接受明确 success 且无 errors；客户端和 worker 双重校验 |
| P1 重启恢复不成立 | 已保存上游 ID 的任务因尝试次数耗尽变成人工重投 | 按任务阶段恢复；已保存 ID 直接 GET；不确定的提交中断禁止自动 POST |
| P1 租约覆盖范围不足 | 长上传/处理期间不续租，旧令牌过期仍可写入 | 后台心跳覆盖整个处理期；续租、阶段更新和发布都检查未过期令牌 |
| P1 阅读顺序破坏 | 标题子节点逆序，group 子节点被放到后续正文后面 | 按父节点位置展开子节点，保持同级顺序 |
| P1 表格口径丢失 | captions/footnotes 的 `$ref` 未解析；脚注没进入分块 | 解引用标题与脚注，并在表格行块中携带口径 |
| P1 来源错位 | 每个正文分块都挂整组来源，第二页内容可标为第一页 | 文本片段与来源同步累积；切分后只保留相关块来源 |
| P2 超长口径越界 | 200 字上限可产生 639 字片段 | 常规长正文、长行遵守上限；表头/标题/注释自身超限时受控拒绝并说明如何调大配置 |
| P2 停止等待无法恢复 | cancel 标志一直保留，任务排队后反复取消 | 用户暂停进入 needs_attention；明确恢复时复用远端 ID；队列不空转 |
| P2 索引并发与中断 | rebuild 可穿过检查重复调用；中断可永久卡住 | 数据库唯一约束阻止同文档并发构建，候选租约过期后可重建，原索引不变 |

| P2 网页旧响应覆盖 | 索引状态与失败轮询分支缺文档序号检查 | 补齐过期响应检查；刷新恢复选中文档；未接入生成能力继续禁用 |
| P2 成功轮询提前改写连接状态 | 旧成功响应在检查文档前清空新文档提示及退避计数 | 校验文档、请求序号和任务 ID 后才修改状态或安排下一次轮询 |
| P2 结构化文件引用与数据库不同 | normalized.json 在绑定解析版本前写出，保存了临时块编号 | 先绑定版本与块编号再落盘；新增文件/数据库一致性回归，结构版本升至 docqa-normalized-3，避免复用旧文件 |

## 测试证据的纠正

原 T16/T17 测试把“B 成功后 A 不可检索”“B 索引失败后没有可用索引”作为预期。这与任务书正好相反，已改成实际查询 A 并验证命中版本及内容。

原 T05 测试手动把数据库状态改成 queued，再证明可以处理 queued；这没有测试真实重启恢复。已改为在保存远端 ID 后模拟进程中断，只推进租约过期，保留 running 现场，由恢复代码自行领取。

原故障脚本接受 HTTP 409 并记录 passed，初次历史 `steps.json` 实际没有证明旧索引可检索。已改为必须 HTTP 200，并要求先建立可用索引。在线收费验证需要显式 `--allow-online-index`；未启用时以未验收退出，不能显示通过。

真实结构夹具现随 `tests/fixtures/docling/` 交付，约 256 KiB；缺失直接失败，不再依赖本机被忽略的 data 目录或绝对路径。工作簿为人工构造样本，不是用户业务数据。

## 升级与后续边界

先停止原 Web 与 worker，再按 README 启动；不能让旧进程与新结构同时写正式库。首次启动自动执行 schema v2 并用 SQLite backup API 生成一致性备份。迁移保留文档、版本、块 ID 与已有向量，不自动 OCR 或调用 embedding。若需回退，停止进程，保留现库及 WAL/SHM，恢复迁移前备份并使用对应旧代码，不能直接让旧代码操作新库。

当前仍需明确的边界：

- OCR 错字、上游阅读顺序、目录页码、公式识别、图表语义不因接入修复自动消失；必须结合原件核对。
- 完整标题/表头/注释自身超出块容量时，本次任务报 `chunking_invalid`，旧版继续可用。调大 `DOCQA_CHUNK_MAX_CHARS` 时仍需符合在线模型输入限制。
- 尚未进行多进程压力、操作系统级网络中断及全部浏览器/恶意输入组合测试；本报告列出实际执行的代表性场景，不沿用原报告的笼统“全部通过”。索引构建失败保留旧索引由离线真实 build 路径的故障注入覆盖，没有故意让收费网关真实失败。
- 不自动清理历史版本和向量，避免丢失仍在使用的索引；后续应设计显式、安全的历史保留策略。
- 2 条 pytest 警告是 Starlette/httpx/anyio 的弃用提示，当前不影响用例通过；本轮未为此整体升级依赖。

密钥检查：读取本地配置中的密钥值，仅比较是否出现在 Git 可见文件，未输出值；匹配文件为空。`.env` 和 `data/` 均未被纳入 Git。
