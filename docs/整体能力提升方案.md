# DocQA 后续能力提升路线

更新：2026-10-20。原2026-10-18十项方案逐字保存在本地整理备份；本文件维护剩余优先级，不重复当前结论。完整验收标准仍在[主任务书](稳定试用版分阶段工程任务书.md)。

## 下一批优先顺序

| 优先级 | 工作 | 验证出口 |
| --- | --- | --- |
| P0 | 独立新资料/问题验收与标注复核 | 按文档/模板分组，模型输出前冻结；已知7题只作回归。事实、引用、条件、覆盖、检索及成本分别报告。 |
| P1 | 扫描表格与文字完整性 | 学段/编号/符号、长格漏字、多层表头/跨度、空白/0；扫描与原生分别验，原图位置可核对。 |
| P1 | 页面分流与补检 | 等有效像素/检测参数消融；验证双向覆盖去重的召回损失；新保留检验漏检收益与误增，不靠置信度自动改数字。 |
| P1 | 阅读顺序与图示 | 双栏/跨栏/图注/表单关系；图中文字与箭头关系分开，后者仍未交付。 |
| P1 | 性能与费用 | 完整无缓存解析→检索→生成、单次及分位耗时、内存/显存/HTTP/token/金额；缓存和未知值明确标注。 |
| P1 | 原文复核体验 | 精确来源区域、候选分歧/不确定性展示和用户反馈；不让实验候选直接成为正式证据。 |
| P2 | 摘要/提取深化与完整恢复 | 重要例外覆盖、摘要长度、指标别名确认、多层摘要和全资料快照恢复；按真实需求独立冻结与验收。 |

本轮已完成代码bug修复及文档整合，不为换架构、上图谱或更大模型预设收益。先按失败属于解析、检索、装入、生成还是校验分类，再做最小对照。

## 质量闭环

1. 冻结原件、标签、问题、必要证据组、不得推断事项和分组；关键数字直接核对原始像素并独立复核。
2. 记录基线与变更变量，保留完整失败；不看输出后修改预期凑通过。
3. 开发集定位并修复，保留集只做预定验收；参与定位的保留转为已用回归。
4. 输出分层分子/分母与未验证项，不合成一个掩盖严重错误的总分；只有真实新增生成才称新在线成绩。
5. 修改分块、嵌入、检索、Prompt或OCR后跑相关回归；通过后按新资料/性能关卡决定是否接正式默认。

## 实施约束

当前账本48/80，余32；本轮审查新增0。后续真实调用先明确范围和上限，不因余额存在自动发请求；失败/不确定同样计数，跨重启/重试不重置。模型配置、旧解析/索引及正式数据不被实验自动修改。

优先复用现有GPU镜像/模型和独立目录，实验工具在scripts。正式升级需基于质量门槛和具体授权；只完成脚本或离线测试不能称生产质量通过。新API兼容、后台状态和浏览器恢复属于工程条件，仍需与语义结果分别验收。

## 当前能力边界

单文档、单轮、非流式；跨文档、多轮记忆、公网/多用户、新供应商自动切换、图形箭头理解和任意文档正确率没有验收。RAG开发7/7与OCR局部CER2.40%各有样本范围，不能互相换算，也不能外推全场景。
