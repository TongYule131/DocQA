# 回归检查策略

2026-10-23 用户已采纳，适用于后续开发、修复、提交和阶段交付。

## 本地许可

**每次本地全量必须先取得用户明确同意；定向检查可直接运行。** “继续任务”“完成后提交”“有提升上线”等普通授权不包含本地全量许可，过去一次许可不能延用。需要全量时先说明触发原因及范围；未获准则记录未执行，继续可独立完成的定向工作。

这一要求也适用于裸pytest、包装脚本及分批跑遍全部测试，不能换命令或伪装CI绕过。`--local-full-approved`只是防误操作参数，只有获准后才能使用，不能代替用户同意。开发约束同时记录在[AGENTS.md](../AGENTS.md)。

## 检查级别

| 修改 | 默认验证 | 是否全量 |
| --- | --- | --- |
| 文档、注释、说明 | 文档链接、版本／配置一致性、diff | 否 |
| 颜色、间距、图标、按钮尺寸 | 真实页面核对、受影响网页检查 | 否 |
| 选择资料、发送、折叠等前端交互 | 网页控制器及直接关联流程 | 通常否 |
| 独立后端功能，未改公共契约 | 模块测试及关联流程 | 通常否 |
| 共享核心、数据、权限、计费与恢复 | 先定向，稳定后建议全量 | 本地须另获同意，或引用对应CI全量 |
| 多模块集成、阶段交付 | 主要流程冒烟及全量验收 | 本地须另获同意，或引用对应CI全量 |

全量触发项：数据库结构／迁移／存储与版本；账号权限与隔离；预扣／重试／幂等／租约／取消和恢复；共享RAG检索／数字及引用校验／输出协议；依赖／启动／全局配置／验证基础设施；多模块集成；定向发现影响扩散。纯样式补丁即使更新本地实例，也不自动升级为全量。

先依据实际代码及依赖判断影响。自动分类器只提供保守建议，未映射文件在PR／main上建议全量；单个模块的配套页面不等于无条件全量。

## CI触发与去重

[工作流](../.github/workflows/rag-quality.yml)保留push、pull_request和workflow_dispatch，由[策略模块](../scripts/regression_policy.py)输出范围：

- 开发分支push默认定向；已有打开的PR时交由PR检查，跳过不代表测试通过。查重API失败仍做定向，不漏检。
- PR及main push按改动分级：文档、普通页面和独立模块定向；核心、集成或未知影响全量。
- 手动运行可选auto、targeted、full；阶段验收可明确选full。没有比较基线时auto按完整仓库保守判定。
- 版本标签push按阶段交付执行全量，不使用开发分支的PR去重。
- 本次消除开发分支push和PR重复；main集成提交单独判断，不把不同源码树的结果冒充复用。将来跨运行复用须核对源码、依赖、策略及环境。

CI清空供应商密钥、使用独立数据目录，不调用真实模型、解析服务或正式数据库。共享认证／请求／流式前端列为核心，其余页面执行现有网页组；后端按模块映射，多后端模块或未知文件保守升级。网页控制器测试不等于视觉验收，离线通过不等于语义正确。

## 本地命令

指定本次改动，可重复给出文件；报告目录必须是data内的新目录：

```powershell
.venv\Scripts\python.exe scripts/run_regression.py --profile targeted --changed-file app/web/knowledge-admin.js --output-dir data/checks-page-001
.venv\Scripts\python.exe scripts/run_regression.py --profile targeted --changed-file tests/test_regression_policy.py --changed-file tests/test_regression_runner.py --output-dir data/checks-policy-001
```

可以直接运行相关`pytest tests/test_某模块.py -q`或单个网页脚本。默认profile为targeted，未指定文件时读取当前Git工作区改动；显式小范围不能报告为整个工作区已验证。`--profile auto`本地判为full且未获准时会停止，不自动升级。定向报告保留全量建议及原因。

仅在用户明确批准**本次**本地全量后使用：

```powershell
.venv\Scripts\python.exe scripts/run_regression.py --profile full --local-full-approved --output-dir data/full-approved-001
```

## 重复执行和结果

- 开发先定向，稳定后安排一次全量；全量后只改文档／样式，沿用已有结果并补相关检查。
- 失败先定位、定向修复，不盲跑全量；没有新增变更、失败或未解疑点，不重复验证。首次失败保留。
- 定向报告为`docqa-targeted-regression-v1`，全量为`docqa-full-regression-v1`；未执行范围明确记录，不累加不同轮次测试数。
- CI与本地分别记录，提交／推送不代表远端CI通过。真实模型验收另按预算计划，不与普通CI绑定。

本规则覆盖历史文档中例行本地全量的执行频率，不改变功能和质量标准。
