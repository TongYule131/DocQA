## 1. 目标、范围与完成标准

在现有工作台实现：**选中文档 → 输入问题 → 检索该文档的有效索引 → DeepSeek 基于片段生成回答 → 后端校验引用 → 页面展示答案和可核对来源**。

第一版明确为单文档、单轮、非流式问答。保留旧解析版本与旧索引继续可用的规则。本阶段不做多文档知识库、多轮会话记忆、查询改写、重排服务、联网搜索、网站抓取、浏览器插件、摘要、信息提取或新模型供应商接入。它们可以作为后续任务，不能挤占当前闭环与验收工作。

最低完成标准：

1. 真实扫描 PDF 在网页中回答可由原文支持的问题，关键事实后有引用，能查看命中片段、解析版本、页码和原件。
2. 相关资料存在但问题缺少条件时提出 1～2 个澄清问题；没有足够资料时说明依据不足，不补造事实。
3. 新解析失败、新索引失败或新旧版本并存时，仍可基于原有效索引问答，并明确标注实际使用的版本。
4. 模型伪造引用、返回无效结构、超时、截断时，页面不得把未经校验的输出当作成功答案。
5. 离线工程测试、真实在线语义评估、浏览器交互验收分别给出证据，不能相互替代。

实施约束：使用中文注释；保留既有功能与测试；在临时目录和临时数据库验证；不自动修改正式数据库、不重建现有用户索引、不提交或推送 Git。不得打印或提交 `.env`、密钥、业务原件、业务数据库；完整在线请求/响应不得进入终端日志、普通页面日志或仓库。公开或人工测试样本可按说明纳入测试目录；其评估证据可保存在 Git 忽略目录，但仍不得保存请求头、真实凭证或模型思考内容。

## 3. 推荐实现分层

```text
POST /api/documents/{id}/questions
  → RagService：前置检查与编排
  → DocumentIndex.search：查询 embedding + 当前有效索引检索
  → EvidenceBuilder：固定版本、去重、预算控制、服务器分配引用编号
  → PromptBuilder：系统规则 + 不可信问题/参考资料
  → DeepSeekModel.generate：一次非流式生成
  → AnswerValidator：严格结构、引用范围、原文引述、状态一致性
  → AnswerRenderer：由已校验的结构生成 Markdown 与引用列表
  → 网页：答案、引用卡片、版本与质量提示
```

建议新增 `app/rag.py`、`app/rag_prompts.py`、`app/rag_validation.py`。上下文组装可独立为 `app/rag_context.py`；不要把全部逻辑堆进路由或提示词字符串。模块命名允许等价调整，但边界和可注入测试入口必须保留。

保持现有 LanguageModel 契约可用，不要求供应商特定 JSON schema / function calling 参数。使用现有字符串生成接口要求 JSON，并在后端严格解析；模型实际兼容性用当前配置实测，不擅自更改用户模型名、端点或思考参数。

本阶段问答不落会话历史、不新增业务数据库表、不新增数据库迁移。每次响应带一次性的 `answer_id` 用于定位请求，不承诺刷新恢复答案或跨进程去重。将来若增加历史记录，另立任务说明数据保留与隐私边界。

## 4. 工程包 A：接口与响应契约

### 4.1 请求和前置检查

沿用 `POST /api/documents/{document_id}/questions`，请求仍为：

```json
{"question":"本年鉴包含多少个部分？"}
```

问题 trim 后非空，最多 4000 字符；拒绝额外字段，不能让调用方提交任意 system prompt、上下文、chunk、模型端点或文档路径。top_k 与预算由服务端配置，不开放为本次请求参数。

检查顺序：请求结构 → 文档存在 → 有成功解析版本 → 有与当前 embedding 配置兼容的可用索引 → 两个在线模型均已配置 → 检索 → 生成。任何前置条件失败不得调用生成；无效请求和不存在文档不得调用查询 embedding。配置状态仅代表配置存在，不等于账户和服务可用。

| 情况 | HTTP / 行为 |
| --- | --- |
| 问题空白、过长或含额外字段 | 422，无在线调用 |
| 文档不存在 | 404，无在线调用 |
| 未解析 / 索引缺失、损坏、模型不兼容 | 409，提示解析或建立有效索引，不自动建索引 |
| API 配置缺失 | 503，不调用外部服务 |
| 正常回答、澄清、依据不足 | 200，以业务 status 区分 |
| 模型输出结构/引用校验不通过 | 502，稳定错误码 `rag_output_invalid`，不能伪装成“资料不足” |
| 上游错误 / 超时 | 沿用现有安全 ModelError、EmbeddingError 映射；超时 504 |

错误统一保留现有字符串 `detail` 字段；RAG 新增错误可另外返回 `code`。不得将上游响应正文、异常堆栈、密钥或完整 Prompt 填进错误响应。

### 4.2 业务响应

新增 `RagAnswer`、`RagCitation` 等明确模型，或兼容扩展现有类型；保留顶层 `answer`、`citations`，不要破坏摘要/提取的占位响应类型。建议契约如下（尖括号表示实际运行值，不能写死）：

```json
{
  "answer_id": "<服务器生成 UUID>",
  "status": "answered",
  "answer": "## 结论\n全书内容分为21个部分。[1]\n\n## 依据与说明\n引用片段明确列出了各部分名称。[1]",
  "clarification_questions": [],
  "citations": [
    {
      "reference_id": 1,
      "document_id": "<当前文档>",
      "chunk_id": "<本次实际证据块>",
      "parse_version_id": "<证据所属版本>",
      "page": 2,
      "quote": "全书内容分为21个部分",
      "sources": [{"format":"pdf","page":2}]
    }
  ],
  "document_id": "<当前文档>",
  "index_id": "<本次检索固定的索引>",
  "parse_version_id": "<本次证据固定的解析版本>",
  "is_old_version": false,
  "is_current_index": true,
  "prompt_version": "rag-qa-v1",
  "retrieval": {"candidate_count": 8, "selected_count": 5, "context_chars": 3800, "truncated": false},
  "quality_warnings": [],
  "limitations": [],
  "timings_ms": {"retrieval": 0, "generation": 0, "total": 0}
}
```

上述数字仅说明字段类型，不是默认结果。`sources` 实际须完整保留已有来源结构，包括 bbox、章节、工作表/单元格、TXT 行号；不能像示例一样一律精简成页码。

字段语义：

- `status` 只允许 `answered`、`clarification_needed`、`insufficient_evidence`。
- `answered` 至少一个带引用的事实；`clarification_questions` 为空。
- `clarification_needed` 有 1～2 个问题；涉及事实的原因/可选范围也带引用；无隐式会话，用户下一次应提交补全后的完整问题。
- `insufficient_evidence` 使用后端固定兜底文本，引用与澄清问题为空；不夹带模型猜测。该状态只描述本次检索证据不足，不断言全文没有答案。
- `citations` 只包含正文实际使用的引用，按 reference_id 排序；编号不强制连续，不允许将全部候选片段冒充已引用来源。
- `is_old_version` 在响应前对比当前预览指针；`is_current_index` 对比当前活动索引。两者只用于展示，不改变本次已固定的证据。
- `timings_ms` 为真实非负耗时；没有调用生成时 generation=0；不返回模型思考过程，也不编造 token 用量或回答正确率。

## 5. 工程包 B：检索、版本固定与上下文预算

### 5.1 保留现有检索语义

复用 `DocumentIndex.search()`，一次提问最多执行一次查询 embedding、一次生成调用。检索不得扩大到其他文档，不得通过搜索整个数据库补齐本次缺失引用。未经主动操作不重新解析或建立索引。

检索结果返回后，将 index_id、parse_version_id、chunk 文本、来源和质量告警作为本次请求快照持有到结束。证据块的 document_id、parse_version_id 必须与快照一致；发现混入其他文档/版本应受控失败，不默默拼接。

回答期间发生以下变化时仍使用固定快照：A 是原有效索引，B 是新解析版本；B 发布、B 索引建立成功、活动索引切换，均不能把 A 的正文与 B 的来源拼成一次回答。可完成旧快照回答并提示版本变化，不得悄悄二次生成或二次计费。原解析和索引不得因 RAG 的成败被修改。

### 5.2 选择证据

1. 按已有分值排序、按 chunk_id 去重，稳定排序规则可用 order_index/ID 解决同分。
2. 初始检索 8 块，最多送入模型 5 块。相似度不是置信度；不要硬编码“低于 0.7 就无答案”。
3. 可配置 `DOCQA_RAG_MIN_SCORE`；默认空值表示禁用分数阈值，配置时要求有限数且在 [-1,1]。阈值上线前必须用正负样本校准，不能仅用同一份扫描文档调参。
4. 没有合格证据时直接返回依据不足，不调用 DeepSeek。存在相关性较弱片段时仍需允许模型判为不足，不能以“top_k 总能返回内容”强迫生成答案。
5. 质量为 invalid 的解析版本不可作为证据。合法 legacy 版本可用，但来源缺失时只能展示已有定位信息并提示限制，不能伪造页码。

### 5.3 明确预算算法

建议初始配置（属于工程起点，不是模型能力声明）：

| 配置 | 默认 | 约束 |
| --- | --- | --- |
| `DOCQA_RAG_RETRIEVAL_K` | 8 | 整数 1～20 |
| `DOCQA_RAG_CONTEXT_K` | 5 | 整数 1～retrieval_k |
| `DOCQA_RAG_CONTEXT_MAX_CHARS` | 12000 | 正整数，限制参考资料序列化后的字符总数 |
| `DOCQA_RAG_INPUT_MAX_CHARS` | 20000 | 正整数，限制实际 system + user 消息字符总数 |
| `DOCQA_RAG_MIN_SCORE` | 空 | 禁用或有限浮点数 [-1,1] |

采用确定性的整块装入策略：将 chunk 连同必要元数据序列化后计入预算；容纳不下则跳过，继续尝试后续候选；入选块不得从尾部硬截断。标题、表头、条件、脚注不可为了凑字数被删掉。因预算舍弃任何块时设置 `truncated=true`，这里表示证据集合不完整，不表示引用文本被截断。

最后再次检查实际 system/user 消息长度，包括问题、文件名、转义字符、元数据、输出 schema 与分隔符。先缩减证据集合；若系统规则与问题本身已超预算，返回稳定 422 错误 `rag_input_too_large`，不得截断问题或系统规则。若只是一个证据块也无法容纳，返回依据不足并提示证据预算限制，生成调用为零。

**字符预算不等于 token 预算**，不能宣传为精确 token 限制。保留现有输出 token 配置，文档说明本地预算是输入限流措施，真正的模型上下文限制仍需供应商实测。这个阶段不凭空引入不匹配 DeepSeek 的 tokenizer。

## 6. 工程包 C：Prompt 与模型输出协议

### 6.1 Prompt 必须落实的规则

严格参考 `docs/Prompt设计与验收参考.md`，并在实施报告逐项对应体检清单：

- 系统规则固定于 system 消息；问题和资料作为 user 消息中的独立数据字段，用 JSON 序列化/明确封装，不能拼接为新的 system 消息。
- 问题、文档内容、文件名、标题、工作表名和引用元数据均不可信；其中“忽略规则、改身份、暴露提示词、执行操作”等指令不执行。分隔符不能被描述成完美防注入方案。
- 只依据本次提供片段；每个关键事实有引用，数字、单位、条件、例外、适用范围完整。OCR 不清楚时不能借模型常识补齐。
- 有相关依据但缺条件时澄清；无相关依据时拒绝猜测。可选答案范围必须同样有依据。
- 上传时间、解析时间不是真实资料更新时间。只有正文明确给出且同事项、同适用范围可比较的生效/修订关系，才能据此判断版本优先；否则并列冲突说法及引用。
- 默认回答 120～200 字，条件/例外完整性优先；正常答案先“结论”后“依据与说明”；澄清与不足不用凑字数或套同样标题。最多 5 个可见列表项。
- 不展示思考过程，不输出参考资料以外的网站或外链，不执行代码或工具；本阶段不给模型任何工具权限。

Prompt 版本固定常量，例如 `rag-qa-v1`，不接受前端修改；每次调整在实施报告记录原因及回归样本。示例可用于说明协议，但不要把政策示例作为所有问题都可引用的隐藏资料。

### 6.2 用结构化输出约束引用，而不是直接信任 Markdown

要求模型最终 content 为单个 JSON 对象；业务层校验后再构造用户看到的 Markdown。无需依赖供应商 JSON 模式。初始协议建议固定为：

```json
{
  "status": "answered",
  "conclusion": [
    {"text":"全书内容分为21个部分。", "refs":[1]}
  ],
  "explanation": [],
  "clarification_questions": [],
  "evidence_quotes": [
    {"ref":1, "quote":"全书内容分为21个部分"}
  ]
}
```

这属于内部模型协议，不能直接作为最终 HTTP 响应。字段都必须存在，拒绝未知字段、重复 JSON 键和不符合状态约束的结构。

前端若采用可信结构渲染，可在最终 RagAnswer 中另行返回已校验的 conclusion/explanation 展示对象；字段须纳入响应类型、接口文档和测试，并与 answer 的 Markdown 内容一致。不得为方便渲染额外返回未经校验的原始模型 JSON。

- answered：conclusion 至少 1 项；conclusion + explanation 总计最多 10 条简短事实，每条 refs 非空；澄清问题为空。
- clarification_needed：conclusion 为空；explanation 至少 1 条带引用的澄清原因，问题 1～2 个；不得在“问题”里夹带无依据结论。
- insufficient_evidence：四个列表全部为空，最终兜底由后端提供。
- 每条事实 text 最多 1000 字符，单个问题最多 500 字符，总事实/问题文本最多 4000 字符；evidence_quotes 每条最多 300 字符。超过限制拒绝，不能截断成“合格答案”。
- `refs` / `ref` 是真正的正整数，拒绝字符串、浮点、布尔值；text 中不允许模型自写 `[n]` 引用标记，编号只能由后端从 refs 渲染。
- 每个被使用的 ref 对应且只对应一条 evidence_quote；引用同一块多次可复用该 quote，若一个短引述无法代表多个论断，另选更合适的块或收缩论断，不可虚构引述。

可以只兼容“整个输出被一对 json 代码围栏包裹”的格式；若支持须有测试。不得从“前言 + JSON + 后记”中用正则捞出 JSON、用 eval 解析、修补字段或自动删掉错误引用后当成功。

## 7. 工程包 D：后端引用校验与降级

程序必须证明的部分：

1. 引用编号由服务端对**最终入选证据**分配；模型只能引用本次确实进入 Prompt 的编号。候选中存在但因预算未送入模型的块也不可引用。
2. 模型不得提供文档 ID、chunk ID、页码、坐标或文件路径；这些全部从本次证据映射复制。按编号查询全库来“补救引用”不合格。
3. 每个 quote 是其对应证据正文的连续子串；可仅统一 CRLF 为 LF，不删空格、改大小写、改数字、删标点来制造匹配。quote 不得为空或纯空白。
4. 输出中的每个事实对象有合法引用；用到的编号集合和引述集合一致。不存在的编号、重复冲突定义、空引用、跨文档/跨版本块一律拒绝。
5. Markdown 中每个事实后紧跟其引用标记，由后端生成，例如 `事实。[1][2]`。不把引用统一堆在末尾，不展示原始未经校验的模型输出。
6. 返回 citations 的 quote 来自通过校验的引述；同时保留对应 chunk 定位，页面可查看完整上下文。一个引用卡片不能声称涵盖未送入模型的邻近正文。

**这些检查只证明结构与来源可追溯，不能证明引用在语义上支持结论。** “原文为 21，答案写 22，但引用编号与引述都真实”仍可能通过形式校验，必须由语义评估发现并计为失败。不要用字符串包含、数字集合检查或第二次大模型自评冒充可靠的事实校验器。本阶段不增加隐藏的第二次模型调用。

引用校验失败统一返回 `rag_output_invalid`，记录非敏感原因码，如 `unknown_reference`、`quote_not_found`、`missing_reference`；日志不得带原文、完整输出和凭证。不自动重试模型、不自动改写答案、不退化为脱离资料的普通聊天。合法的依据不足才返回 200 + insufficient_evidence。

## 8. 工程包 E：网页交互与调用成本

1. 正式接通现有问答框；要求文档可用、有效索引、两个模型已配置且无问答请求进行中。summary/extract 继续禁用；capabilities 仅把 rag 更新为 true，保留其他真实能力状态。
2. 点击提问后显示“正在检索资料并生成回答”；非流式不伪造 token 输出或进度百分比。可显示总等待时间，结束后恢复按钮。
3. 请求携带当前 document_id 的快照；成功和失败分支均校验请求序号及选中文档，旧响应不得覆盖新文档。轮询刷新文档状态不得清空正在生成的答案区或错误地重启问答。
4. 第一版可沿用 busy 锁定文档切换；若允许切换必须丢弃迟到响应。无论是否锁定，都要覆盖其他页面/服务端导致的版本变化。
5. 不用普通 `JSON.stringify(result)` 代替产品展示。渲染结论、说明、澄清问题、依据不足提示和引用卡片。优先使用可信结构 + createElement/textContent 安全生成有限 Markdown 对应的标题、段落和引用按钮；无需支持任意 HTML/图片/外链。
6. 如选用 Markdown 库，必须禁原始 HTML、远程图片和不安全 URL，并给出固定依赖与 XSS 测试。模型文本里的 `<script>`、`img/onerror`、`javascript:` 只能作为文字或被安全拒绝，不能执行或触发外部请求。
7. 点击 `[n]` 能定位对应引用卡片。卡片显示引述、文件名、来源位置、解析版本；能打开已有版本预览与原件。PDF 支持页码跳转；DOCX/XLSX/TXT 按真实来源展示，不伪造 PDF 页码。已有接口只支持版本级预览时，如实显示“查看引用版本”，不要声称已精确高亮对应字符。
8. 历史版本答案清楚提示“回答依据历史解析版本”；模型调用期间索引切换后也须提示。质量告警单列，不要让模型编造它们；引用段有缺公式缓存、OCR 限制等问题时保留相关告警。
9. 澄清问题显示为待补充条件；本阶段不保存多轮历史。提示用户把条件补进完整问题再提交，或给出可编辑的“原问题 + 补充信息”输入模板，不把上一轮模型答案作为事实传回。
10. 回答期间禁用重复点击和 Enter 重复提交，错误后可手动重试；前端、服务层、模型 SDK 均不得自动重发生成请求。页面刷新、列表刷新、解析轮询、能力探测不触发问答或收费模型调用。
11. 本阶段没有持久化幂等保证：两个独立合法 POST 可以产生两次费用，刷新/浏览器中断也不代表上游停止计费。README 如实说明；不要复用解析任务表或声称 exactly-once。若实现取消按钮，只能承诺停止等待，不能承诺已取消供应商生成。

首次使用时在问答区域说明：问题会发送给 embedding 服务，入选的文档片段与问题会发送给配置的 DeepSeek 服务，点击提问会发生在线调用。页面不显示密钥，状态查询不自动探测账户。只在本地服务中运行，不扩展成无鉴权公网部署。

## 10. 离线验收矩阵 R01～R26

默认离线测试不能读取真实密钥、依赖 Docker 或用户 data 目录。注入 mock embedding/模型，但编排、上下文构建、输出解析、校验和路由必须是真实生产路径。至少一个 API 集成测试使用现有 SDK + MockTransport 返回响应，不得所有测试都替换整个 RagService。

| 编号 | 场景 | 必须证明 |
| --- | --- | --- |
| R01 | 已有功能回归 | 解析、版本、旧索引、上传识别、错误脱敏仍通过，其他未接能力不误启用 |
| R02 | 请求与前置检查 | 空白/超长/额外字段/不存在/未解析/无索引/缺密钥，状态正确且不误调用模型 |
| R03 | 正常有据回答 | 响应和网页答案源于实际模拟模型输出，引用到入选真实 chunk，无写死回复 |
| R04 | 检索范围与候选去重 | 其他文档同词片段不混入，重复 chunk 不重复编号，不偷查全库补引用 |
| R05 | 阈值与无合格证据 | 空证据/低于配置阈值不调用生成；无阈值时不假设所有高分均相关 |
| R06 | 上下文预算 | 超长正文、文件名、元数据、转义字符均计入实际消息；整块舍弃，不删表头/例外；预算不足不调用生成 |
| R07 | 伪造/未入选引用 | 未知编号、只在候选中但未送模型的编号、跨文档/跨版本映射被拒绝 |
| R08 | 原文引述 | 真实连续子串通过；改数字、移花接木、拼接不连续片段、空引述被拒绝 |
| R09 | 输出协议 | 坏 JSON、重复键、未知字段、布尔引用编号、空正文、状态矛盾、超长输出被拒绝 |
| R10 | 引用完整性 | 每条事实 refs 非空；未使用引述、缺失引述、模型自写编号、冲突重复定义被拒绝 |
| R11 | 澄清 | 1～2 问、原因有据；页面不会把澄清显示成已有明确结论 |
| R12 | 合法依据不足 | 200 + insufficient_evidence、固定兜底、引用为空；与模型校验失败的 502 区分 |
| R13 | 时间/冲突规则 | Prompt 与证据包不把上传时间当资料更新时间；真实效果另做语义验收 |
| R14 | 注入边界 | 资料/问题/文件名中的角色标记仍作为不可信数据，未进入 system 或触发工具；效果另做真实模型测试 |
| R15 | PDF 与 Office 来源 | 完整保留 bbox、章节/表号、工作表/单元格、TXT 行号；Office page=None 不转成第一页 |
| R16 | 质量告警 | 无缓存公式不变为 0，OCR/公式缺失提示可见；invalid 版本拒绝；legacy 缺来源明确提示 |
| R17 | B 解析失败 | A 问答仍成功且来源/索引是 A；不能把 409 当成通过 |
| R18 | B 解析成功、B 尚未建索引 | 基于 A 回答，提示历史版本，不使用 B 的内容或来源 |
| R19 | B 索引构建失败 | A 仍可问答；候选失败不破坏 A |
| R20 | 生成期间活动指针改变 | 在模型回调中真实发布/切换 B，本次答案仍全为 A，提示版本变化；下一请求使用 B |
| R21 | 上游超时/错误/截断 | 安全错误、无 raw response/reasoning_content 泄露；调用次数不因失败自动增加 |
| R22 | 输出与日志泄露 | 模拟凭证/路径置于上游错误；HTTP、页面与应用日志不包含它们，配置 repr 无密钥 |
| R23 | 网页状态/竞态 | 忙碌禁重复提交，错误恢复，切换或刷新后的迟到响应不覆盖新状态；每个有效用户提交对应一次问答请求 |
| R24 | 网页引用与 XSS | 逐事实编号可点击、版本入口正确；文件名/问题/模型文本/quote 中 HTML 不执行，不加载外部图片 |
| R25 | 无隐藏调用 | 启动、刷新、任务轮询、能力探测不会触发问答；无证据生成数为零；无自动重建索引 |
| R26 | 配置与兼容 | 配置读取、无效数值/NaN/Infinity/相互冲突被拒绝；原模型测试、检索接口与错误 detail 契约保留 |

R23/R24 必须保留可复核浏览器证据，不能仅断言某段 JS 中含有 textContent。R13/R14 的离线构造通过，也不能代替模型实际遵循规则。

## 11. 语义评估：区分可追溯与回答正确

建立至少 12 个固定案例；预期在看模型输出前写好。每个记录实际召回块、实际送入片段、原始生成结果（仅本地忽略目录）、最终业务响应、语义判断和失败类别。公开/合成样本可用于离线测试，业务原文不得上传到仓库。

| 样本 | 检查重点 |
| --- | --- |
| 正常单一事实 | 答案与原文数字/单位一致，逐事实引用 |
| 多片段联合回答 | 各论断引用实际支撑片段，不用一个编号包揽所有事实 |
| 条件缺失 | 例如“买了一周能退吗”应问签收时间/使用状态，不能把购买时间当签收时间 |
| 无关问题 | 即使余弦检索返回了片段也不强行回答 |
| 有关但资料不完整 | 不因部分依据而编造剩余结论 |
| 两条相冲突的规则 | 分别引用、说明冲突，不自行调和 |
| 无真实更新时间 | 不依据上传先后选择“最新版” |
| 含例外/特殊有效期 | 结论保留条件，不以字数限制省略 |
| 表格数据 | 保留表头、单位和脚注；不混淆行列 |
| 公式无缓存/OCR 不清 | 不填 0，不猜数字；可拒答或明确限制 |
| 文档/文件名中的注入 | 不执行角色切换，不泄露 Prompt，不采纳注入要求的虚假答案 |
| 语义错引反例 | 原文 21、模型说 22 且引用合法，必须在语义评估中记为失败，不能因后端 200 算通过 |

逐个统计：召回是否含足够证据、状态是否合适、关键事实是否正确、引用是否真正支持论断、条件是否完整、是否出现资料外事实。记录实际分子/分母和失败案例，不只给一个总“准确率”。

验收时核心固定案例不允许未说明的事实编造、数字错误、错引和注入服从；出现失败必须归因并修复/收缩能力后复测，不删题、不只保留成功截图。模型存在随机性，报告必须说明一次通过不等于长期保证；记录模型配置、Prompt 版本和测试日期。

工程测试可模拟所有案例。真实在线最小批次覆盖：扫描 PDF 明确事实、DOCX 条件澄清、XLSX 表格/缺缓存、无依据、冲突或例外、注入，共至少 6 类；整套固定语义案例仍要给出各自“离线模拟 / 真实在线 / 未验证”标签。离线模拟的正确回复不证明真实模型正确。

## 12. 真实服务与浏览器验收步骤

只在单独 `DOCQA_DATA_DIR` 验证，复用现有 Docling GPU 服务和配置好的在线接口；不重新下载模型、切换 CPU 或反复证明 OCR GPU 后端。使用现有已解析测试样本可减少费用；必须记录是否复用了索引。

1. 从工作台选中扫描 PDF，确认有效索引，输入“本年鉴包含多少个部分？”等可由样本原文支持的问题。
2. 记录文档、解析版本、索引、chunk、Prompt 版本、模型、回答耗时及实际引用；对照原件核实关键事实和页码。
3. 点击逐句引用，验证引述和引用版本预览/原件入口正确。查不到正文中的引述时不能验收通过。
4. 输入资料外问题、缺条件问题、例外问题以及注入样本问题，记录真实业务状态和模型行为，不只测“连通成功”。
5. 验证 A 有效时 B 失败/B 发布未索引/B 索引切换的问答行为。故障在测试环境注入，生成中切换的确定性竞态由离线测试补充。
6. 断开或模拟生成服务故障，确认安全报错、恢复控件、没有自动重试计费；用真实浏览器检查重复提交和恶意内容展示。
7. 重启 Web 后再次提问仍可使用已持久化索引；问答结果本身不持久化，因此刷新后答案清空属于明确的第一版行为，不应伪装成历史恢复。

真实调用只由显式操作/在线脚本触发，脚本输出实际 embedding/生成请求数；不得为了凑通过次数无限调用。缺配置或网络失败时，完成其他工作并标注“真实在线语义/网页验收未完成”，不能用离线 mock 的成功替代。

## 13. 交付格式与验收结论

交付至少包含：

1. 实现文件清单、中文注释、接口类型、Prompt 版本、配置及 README 更新。
2. 原基线与新增测试的命令和结果；R01～R26 每项对应测试名/浏览器记录/未验证说明。
3. 语义案例及逐条评估结果；失败案例、诊断、修正和复测记录。
4. 真实在线请求数量、模型/配置、文档/版本/索引标识、引用与原件核对结果；原始证据存 Git 忽略目录。
5. Git diff 自检与密钥检查。不得自动 commit/push，不提交真实 API 响应、业务原件或密钥。
6. `docs/RAG问答接入实施报告.md`，明确剩余限制及仍未通过的验收项。

最终分别给出：**离线工程检查通过 / 真实在线 RAG 语义评估通过 / 网页端到端与故障验收通过**。部分完成时只标对应层级，不能笼统写“生产级 RAG 全部完成”。
