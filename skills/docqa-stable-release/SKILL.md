# DocQA 稳定试用版实施与验收

本 skill 服务于 DocQA 项目。按用户当前请求选择实施、续作或独立验收；只请求讨论／编写任务时，不擅自启动实现。用户的新指令优先于本文件。DeepSeek 等环境没有 skill 加载机制时，可直接阅读本文件作为执行规范，不依赖 Codex 专用工具。

## 定位项目与读取依据

项目通常在 `D:\python\DocQA`；也可从用户指定目录寻找含 `pyproject.toml`、`app/`、`docs/` 的 DocQA 根目录。下列路径均相对**项目根目录**，不是相对 skill 的安装位置。

1. 先读`docs/README.md`和唯一的`docs/接力对话.md`。`docs/阶段00-验收标准与开发约束.md`承接分析协议与A01～A26；原任务书完整字节在归档保留，不另复制标准。
2. 读取 `docs/接力对话.md`、`docs/阶段04-真实语义验收与提取改进.md` 和 `docs/阶段05-代码审查与加固.md`，确定当前结论、停止条件及未提交工作。文档已按阶段00～07整合，当前任务只看阶段07，预算只看阶段04，其他入口从 `docs/README.md` 查找。
3. 依据当前阶段读取任务书指向的代码、README、测试及 `docs/阶段03-稳定版工程与恢复.md`；解析和问答历史见阶段01／02。独立验收时另外读取实际原始证据，旧报告原文在文档整理备份中保留。

任务书缺失时先在项目 `docs/` 中查找；仍缺失就说明所缺依据，不臆造新验收标准。skill 不携带业务原文或密钥。

当前产品化已扩展至团队知识库、会话与流式；原M0～M6标准不代表新增能力清单。续作先读阶段05、阶段07及阶段06产品说明，按用户当前授权确定部署和迁移范围；历史版本号与限制仅用于对应阶段，不据此倒退当前功能。

## 继承约束

- RAG v5固定集12/13及D-RAG-01延期是历史状态；后续v6最新13/13，首次失败保留。当前版本、工程计数及语义边界以阶段04／05为准，不能把历史成绩当新代码实测。
- 不改 Prompt、judge、题目预期或负例凑通过；新共享代码引发的既有功能回归必须修复。历史已通过原题不自动重复收费执行。
- 先查看 Git 状态与差异，保留现有未提交修改。不自动 commit／push／PR，不改无关模型、网关、thinking 或依赖。
- 只在独立 `DOCQA_DATA_DIR` 或临时库实施和验证，启动前显式核对路径。可编写和测试迁移，不对正式库执行迁移，不用新版服务启动正式库。已有活跃 SQLite 备份使用 SQLite backup。
- 复用现有 Docling/GPU 部署与缓存。摘要／提取使用固定解析版本，不依赖 embedding 索引，不自动解析或建索引。
- 中文注释解释不明显的约束；密钥、原始模型响应、业务原件、数据库和截图只留规定的本地位置，日志不含凭证或模型思考。

## 实施与续作

按 M0→M6 的依赖推进：基线设计 → 分析任务与结果 → 提取 → 摘要 → 工作台 → 启停恢复 → 完整交付。阶段内常规实现选择自行决定，出口通过后继续，不为每阶段例行请求确认。

需要始终守住的实现不变量：

- 任务固定解析版本、输入清单和计划；结果持久化，旧成功结果不因新尝试失败丢失。
- 持久化幂等、原子领取、租约令牌、逐请求预扣预算和已校验检查点；不确定的在途调用转 needs_attention，不能自动重发。
- 输出只接受严格协议和本次输入范围内的原文引用。只允许 CRLF 归一化，不清洗错误引述、不静默补引用；形式校验不代替语义验收。
- 长文档显式规划批次与汇总。中间摘要不是原文，最终事实仍核验到真实输入来源；未完成的覆盖不能发布为全文成功。
- 提取保留数字、单位、时间、主体及条件；摘要保留重要例外与冲突。空项、缺值、无依据与模型失败分开表示。
- 刷新、轮询、本地分析预算规划、能力查询、历史查看及导出不触发任何收费调用；取消不承诺上游停止计费。

维护对应阶段汇总，映射验收项、实际测试和证据，避免另建重复日报／实施／验收报告。恢复对话时先读唯一接力对话、阶段04／05／07与持久化调用账本，从未完成项继续，不重新运行全部历史在线测试。能力或外部服务不可用时先完成可独立进行的离线工作，如实标注未验证。

## 调用预算

本 skill 本身不授权付费调用。默认离线；只有用户执行指令明确允许本阶段在线验收及总上限后才运行。任务书中的 24 次只是原实施预算建议；当前阶段必须核对用户实际授权、阶段04和持久化账本，不能据此获得新额度。

额度按一次阶段交付累计，包含失败及不确定调用，跨脚本、重试、重启和换对话保留。历史 RAG 的 30 次预算已用完，不能复用。任务自身默认 8 次的上限与阶段在线总预算同时生效。无余量、缺授权或缺样本时不调用，保留未完成项；不换账本、删题或反复请求凑通过。

## 独立验收

用户要求验收时先不信任实施报告中的通过结论。对照任务书 A01～A26，检查工作区差异、实际协议、迁移和预算，再在独立环境运行必要的离线与浏览器验证。优先复核保存的在线原始证据；新在线复验需要用户另行给出预算。

逐题区分工程校验、引用可追溯、事实正确、条件完整、覆盖完整。未执行、网络失败或证据缺失不能计为通过；故意错误的语义负例必须失败。旧网页证据不能冒充新页面已测。

发现问题写出位置、触发条件、影响和可复现证据。原实施报告保留归档；独立结论在对应阶段汇总中与实施记录区分。若用户还授权修复，修复后重新验证受影响项，保留原失败与复验结果。

## 交付表达

分别报告：离线工程、提取在线语义、摘要在线语义、网页与启停恢复、原有 RAG 延期项。附实际调用数、证据目录、未验证范围、迁移／正式发布状态和未提交修改。任务或接口完成不等于语义验收通过；新功能通过且带 RAG 已知限制的本地试用版，可以与“全部语义问题已解决”清楚区分。
